## Context

- Шапка меню — `Brand` в `web/src/app/AppLayout.tsx`: `Logo` из `ui/AuthLayout.tsx` (буква «A»
  на `bg-primary`) и `me.orgInfo.name`. Рисуется трижды: боковая панель, выезжающее меню,
  верхняя полоса на телефоне.
- Филиал и его смена — `BranchSwitcher` в `app/AccountMenu.tsx`: подменю появляется при двух
  филиалах и больше, список — `myBranchesQuery` (`auth/my-branches`), смена — `useSwitchBranch`
  (перевыпуск токенов, сброс кэша прежнего филиала, перечитывание сессии).
- `auth/my-branches` уже отдаёт только доступные сотруднику филиалы: `DbBranches.list()`
  фильтрует по `ctx.employee.availableBranches`.
- Ассистент — `AssistantHost`: кнопка-триггер в верхней полосе и `EditSheet` с диалогом.
- Организация — агрегат `domain/org/` (`current()` / `withNew(name, timezone)` / `save()`)
  с процессным кэшем `LocMemCachedOrganizations`; настройки — `org/settings` и
  `org/settings/update`, панель `settings/org/OrgSettingsSheet.tsx`. `OrgInfo` в `auth/me`
  собирается в `routes/ProfileRoutes.kt` из `organizations.current()`.
- `components/ui/sheet.tsx` уже умеет `side="bottom"` — шторка для телефона без новых
  зависимостей.

## Goals / Non-Goals

**Goals:**
- Один переключатель филиала — в карточке клуба — на всех ширинах.
- Цвет клуба — закрытое множество значений от БД до UI, без проверки строк в callsite.
- Не трогать маршрутизацию, права и модель филиалов.

**Non-Goals:**
- Права на «Управление филиалами» и на настройки организации (отдельное изменение). Пункт
  «Управление филиалами» показывается всем, кому виден список, — так же, как сейчас открыт
  раздел `/settings/branches`.
- Загрузка логотипа клуба, цвет на уровне филиала, свободный выбор цвета.
- Перекраска остального интерфейса в цвет клуба: `--primary`, кнопки, бейджи остаются синими.
- Нижняя панель навигации на телефоне.

## Decisions

### Палитра — перечисление в `shared`, а не hex-строка

`ClubColor` — `enum` в `shared` (`BLUE`, `SKY`, `TEAL`, `GREEN`, `VIOLET`, `FUCHSIA`, `PINK`,
`RED`, `ORANGE`, `SLATE`), сериализуется именем. В БД — `TEXT NOT NULL DEFAULT 'BLUE'` с
`CHECK` по тем же именам. Значения цветов живут только в вебе — CSS-токены
`--club-<name>` в `index.css` со своими значениями для тёмной темы.

Почему: невалидный цвет не проходит десериализацию (принцип «Parse, don't validate» из CLAUDE.md),
контраст гарантируется подбором палитры, а не проверкой пользовательского ввода; сервер не
знает про оттенки и тёмную тему.
Альтернатива — hex с проверкой контраста на сервере: открывает светло-жёлтые монограммы,
тянет цветовую математику в `domain/`, ломает тёмную тему.

### Цвет — часть агрегата `Organization`, а не отдельный агрегат

`Organization` получает `clubColor`; `withNew(name, timezone, clubColor)`; `org/settings`
и `org/settings/update` расширяются полем `clubColor`, `OrgInfo` — тоже. Миграция одна:
колонка с умолчанием покрывает существующие и новые организации, `INSERT` в `DbAuth` не
меняется.

Почему: цвет редактируется в той же панели и тем же запросом, что название и часовой пояс, и
читается вместе с ними; кэш `LocMemCachedOrganizations` и его инвалидация работают как есть.
Альтернатива — агрегат по образцу `attendancecontrol` / `clientcard` (своя таблица и маршруты):
оправдан для отдельной панели, здесь даёт второй запрос на сохранение одной формы.

### Монограмма — чистая функция в вебе

`monogramOf(name)`: слова по пробелам и дефисам, первые буквы первых двух слов в верхнем
регистре; одно слово — одна буква. Тест на кириллицу, латиницу, кавычки («Олимп»), лишние
пробелы. Сервер монограмму не отдаёт: это вопрос отображения.

### Карточка — один компонент, два способа раскрытия

`ClubCard` получает `me`, список доступных филиалов и режим. Режимы:
`static` (один филиал — `<div>`, без фокуса), `menu` (компьютер — `DropdownMenu` с
`DropdownMenuRadioGroup`), `sheet` (телефон — `Sheet side="bottom"` с `radiogroup`).
Список филиалов загружается тем же `myBranchesQuery`, но сразу при показе раскладки, а не при
открытии меню: от числа филиалов зависит, кнопка ли карточка. Пока список грузится, карточка
показывается статичной.

Альтернатива — общий `DropdownMenu` на телефоне: дешевле, но пункты мелкие и меню прыгает
под край экрана; шторка уже есть в `components/ui`.

### Смена филиала — тот же `useSwitchBranch`

Логика переключения не меняется, меняется место вызова. `BranchSwitcher` удаляется из
`AccountMenu.tsx`, страница `/settings/switch-branch` остаётся как есть.

### Ассистент на телефоне — пункт меню аккаунта

`AssistantHost` разделяется на триггер и панель: панель с состоянием остаётся в раскладке,
открытие поднимается в `open`/`onOpenChange`. На широком экране триггер — кнопка в полосе, на
узком — пункт `DropdownMenuItem` в меню аккаунта; после закрытия панели фокус возвращается на
кнопку меню аккаунта (требование «Панель помощника» в `web-client/ai-assistent` — возврат к
кнопке открытия).

## Risks / Trade-offs

- [Синий клуб рядом с синим знаком Athletica внизу меню сливается] → знак продукта
  приглушённый и маленький; при жалобах — сделать его серым, это правка одного класса.
- [Процессный кэш организаций при нескольких экземплярах сервера отдаёт старый цвет до
  перезапуска] → тот же риск уже есть для названия; цвет — не критичные данные. Не решаем здесь.
- [`auth/my-branches` теперь грузится на каждой странице] → один короткий запрос на сессию,
  ключ кэша общий с прежним подменю, список меняется редко.
- [Сотрудник ищет смену филиала в меню аккаунта по привычке] → карточка со стрелками — первый
  элемент меню; изменение UI отмечено в описании PR.

## Migration Plan

1. Миграция Liquibase: колонка `club_color` с умолчанием `'BLUE'` и `CHECK`. Откат —
   `DROP COLUMN`, данные не теряются, кроме выбранных цветов.
2. Сервер и `shared` выкатываются вместе с вебом (схемы контрактов меняются в одном PR).
   Старый веб игнорирует лишнее поле в `auth/me`; новый веб против старого сервера не
   выкатывается.
