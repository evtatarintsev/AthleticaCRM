# Proposal

## Why

Сотрудник, забывший пароль, сейчас не может вернуть доступ: сменить пароль можно только
через профиль, а для этого нужен старый пароль. Сброса пароля по почте нет, поэтому сделать
это может только администратор, и ему нужен для этого штатный инструмент, а не ручной
`UPDATE` хеша в базе.

## What Changes

- Новая группа административных команд `admin user` для операций над пользователями.
  Пользователь (`users`) не принадлежит одной организации: логин уникален во всей системе,
  а один пользователь может быть сотрудником нескольких организаций. Поэтому группа отдельная,
  а не внутри `admin org`.
- Новая команда `admin user reset-password <логин>`. Она задаёт пользователю новый пароль
  без проверки старого.
- Новый пароль вводится только интерактивно: скрыто и дважды. В командной строке
  его передать нельзя, поэтому он не попадает в историю shell и в список процессов.
- Пустой пароль и несовпадение двух вводов отклоняются, данные при этом не меняются.
  Других проверок нет: на сервере политика паролей не применяется нигде.
- Если логин не найден, команда пишет сообщение в поток ошибок и завершается
  с ненулевым кодом возврата.
- Описание команды добавляется в `docs/cli.md`.

Известные ограничения, которые в это изменение не входят:

- Действующие сессии пользователя не завершаются. JWT нигде не хранится, а при обновлении
  токена проверяется только то, что пользователь существует и сотрудник активен. Поэтому
  выданные до сброса токены работают до конца своего срока. Если аккаунт был скомпрометирован,
  сброс пароля проблему не решает.
- Пользователя не заставляют сменить пароль при следующем входе.
- Сброс не пишется в журнал аудита: журнал ведётся по организациям, а пользователь
  к одной организации не привязан.

## Capabilities

### New Capabilities

_нет_

### Modified Capabilities

- `admin-cli`: иерархия административных команд дополняется группой `admin user`;
  добавляется требование к сбросу пароля пользователя.

## Impact

- `server/src/main/kotlin/org/athletica/crm/admin/`: новые команды `UserCommand` и
  `ResetPasswordCommand`, сброс пароля в обход `RequestContext` (по образцу `OrgSearch`),
  регистрация в `athleticaCommand()` и `AdminDi`.
- Используется существующий `PasswordHasher`. Схема БД, HTTP API, `shared` и `web/`
  не меняются, контракты перегенерировать не нужно.
- `docs/cli.md`: синопсис и раздел о новой команде.
- Тесты: `AthleticaCliTest`.
