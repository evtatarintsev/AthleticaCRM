## Why

Новая организация начинает с пустого справочника источников клиентов: чтобы вести статистику привлечения с первого клиента, владельцу приходится самому придумывать список. Самодельные списки получаются либо слишком дробными, либо с пересекающимися значениями («Instagram» и «Соцсети»), и статистика по ним теряет смысл. Кроме того, у источника есть только название: сотруднику при оформлении клиента неясно, куда отнести, например, листовку у зала — и он выбирает наугад.

## What Changes

- При регистрации организации справочник источников заполняется стартовым набором из 10 значений на языке регистрации: Рекомендация, Соцсети, Таргетированная реклама, Поиск в интернете, Карты и отзывы, Сайт, Вывеска / проходил мимо, Мероприятие, Школа / детский сад, Другое. Дальше организация правит справочник сама: предустановленные источники ничем не отличаются от созданных вручную.
- У источника появляется **необязательное пояснение** — что сюда относится (до 500 символов). Предустановленные источники создаются с пояснениями.
- API источников (`lead-sources/list`, `create`, `update`) получает поле `description`.
- Веб: панель справочника источников в настройках показывает и редактирует пояснение; при выборе источника в карточке клиента под полем показывается пояснение выбранного источника.

### Non-goals

- Заполнение справочника существующим организациям — у них уже свои источники, смешивать списки опасно.
- Пояснения у источников, создаваемых импортом CSV: остаются пустыми.
- Признак «системный» / запрет удаления предустановленных источников.
- Desktop-клиент (`composeApp`) не поддерживается: пояснение в нём не показывается и не редактируется.
- Пояснения для других справочников (залы, дисциплины, филиалы) — механизм в вебе делается переиспользуемым, но включается только для источников.

## Impact

- **БД**: миграция — колонка `lead_sources.description`.
- **server**: `usecases/auth/SignUp.kt` (заполнение), `domain/leadSource/*` (поле пояснения, аудит), `i18n/Messages.kt` (названия и пояснения RU/EN), `routes/LeadSourcesRoutes.kt` (валидация длины), `usecases/clients/import/ImportClientsCommit.kt` (новая сигнатура создания источника).
- **shared**: `api/schemas/leadSources/*` — поле `description` в запросах создания/обновления и в ответе списка.
- **web**: перегенерация `api/generated/contracts.ts`; `settings/directory/*`, `settings/directories.ts`, `clients/ClientFormPage.tsx`, словари `i18n/ru.ts` / `en.ts`.
- **composeApp**: изменений нет; переименование источника из desktop-клиента сбрасывает пояснение (клиент не поддерживается, риск принят).
