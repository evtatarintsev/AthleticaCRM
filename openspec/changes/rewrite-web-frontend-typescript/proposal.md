## Why

Веб — основной клиент продукта, и Compose Multiplatform на вебе для него не подходит. Интерфейс рисуется в `<canvas>` поверх Wasm, а не в DOM. Отсюда проблемы, которые нельзя починить точечно: не работают автозаполнение и менеджеры паролей, pull-to-refresh на телефоне, поиск по странице, выделение текста, переводчик и скринридеры; текст в пунктах меню иногда пропадает до перезагрузки; первая загрузка тяжёлая (~17 МБ wasm). Каждый новый экран на KMP увеличивает объём будущего переноса, поэтому переезжать нужно сейчас.

В [#82](https://github.com/evtatarintsev/AthleticaCRM/pull/82) новый клиент на TypeScript + React уже работает по `/web/` и умеет вход и регистрацию. Это изменение доводит перенос до конца.

Главное условие — **максимальная строгость типизации**. KMP давал совпадение контрактов с сервером бесплатно: общий `shared` и один компилятор. Переход на TypeScript не должен это ослабить. Контракты генерируются из тех же Kotlin-схем, данные от сервера проверяются на границе, а компилятор и линтер настроены так, что `any`, непроверенные приведения типов и неполные `switch` не проходят сборку.

## What Changes

- **Строгий TypeScript как неотключаемый барьер сборки.** Все флаги строгости `tsconfig` включены, в том числе `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `noPropertyAccessFromIndexSignature`, `erasableSyntaxOnly`. ESLint работает с проверкой типов (`strictTypeChecked`): запрещены `any`, `!`, `as` (кроме `as const`), `@ts-ignore` и `@ts-expect-error`, непокрытые ветки `switch`, «висящие» промисы. Покрытие типами — 100%. Любое нарушение роняет `npm run check`, Docker-сборку и CI.
- **Контракты API генерируются из `shared`.** Gradle-задача обходит дерево маршрутов Ktor и дескрипторы kotlinx.serialization. На выходе — zod-схемы и выведенные из них TS-типы для всех ~95 эндпоинтов: путь, метод, тип запроса и ответа. Идентификаторы сущностей становятся брендированными типами (`ClientId` нельзя передать вместо `GroupId`). Sealed-иерархии превращаются в размеченные объединения, даты и время — в брендированные строки ISO. Сгенерированный файл лежит в репозитории, CI падает, если он устарел.
- **Ответы сервера проверяются на входе (parse, don't validate).** Клиент декодирует каждый ответ сгенерированной схемой. Несовпадение с контрактом — отдельная типизированная ошибка, а не молчаливая порча данных в UI.
- **Сервер всегда сериализует поля со значениями по умолчанию** (`encodeDefaults = true`). Иначе в ответах пропадают поля, равные дефолту, и в TS все такие поля приходится делать необязательными. KMP-клиент это изменение не ломает.
- **Каркас приложения:** сессия на cookie с обновлением токена при 401, основная раскладка с навигацией, переключение филиала, типизированные маршруты (TanStack Router), загрузка данных через TanStack Query, формы через TanStack Form + zod, компоненты shadcn/ui (Radix), локализация RU + EN с проверкой полноты словарей компилятором.
- **Перенос всех экранов KMP-клиента по фазам.** Главная, расписание, клиенты, группы, сотрудники, задачи, сообщения, настройки — 45 экранов с функциональным паритетом. Каждая фаза выкатывается отдельно. Пока перенос не закончен, разделы, которых ещё нет в React, открываются в KMP-клиенте по общей сессии.
- **Переключение `/` на React-клиент** после переноса последнего раздела. Старые адреса KMP-клиента перенаправляются на новые.
- **BREAKING (для деплоя), последняя фаза:** удаляются wasm-таргет `composeApp`, `Dockerfile.web`, сервис `web` в compose и сборка его образа в CI. Десктопная (jvm) сборка `composeApp` и модуль `shared` остаются.

Вне скоупа, сознательно:

- **Мобильные приложения.** Android/iOS на Compose Multiplatform — отдельное изменение. `shared` и ViewModel-и сохраняются.
- **SSR и публичные страницы** (лендинг, публичное расписание, онлайн-запись). В CRM за логином они не нужны.
- **Новая функциональность и редизайн.** Переносим поведение как есть, кроме мест, где старое поведение — следствие ограничений Compose (например, выбор филиала при входе).

## Capabilities

### New Capabilities

- `web-client/type-safety`: требования к строгости компиляции и линтинга TypeScript и к тому, где они применяются (локально, Docker-сборка, CI).
- `web-client/api-contracts`: генерация контрактов из `shared`, проверка ответов на границе, брендированные идентификаторы, контроль устаревания сгенерированного кода, сериализация полей по умолчанию на сервере.
- `web-client/app-shell`: сессия и обновление токена, навигация и раскладка, переключение филиала, локализация RU/EN, базовый путь `/web/` → `/`, сосуществование с KMP-клиентом во время переноса.
- `web-client/migration`: паритет разделов с KMP-клиентом, порядок фаз, условие переключения `/` и удаления wasm-клиента.

### Modified Capabilities

- `group-schedule-editor`: требование к узкому экрану задано в `dp` (единица Compose). Оно переформулируется в CSS-пикселях, чтобы оставаться проверяемым в веб-клиенте.

## Impact

- **Новый и изменённый код:** `web/` — весь новый клиент; существующие вход и регистрация переписываются под строгие правила (сейчас там есть `as` и `!`).
- **Сервер:** `RouteWithContext` записывает в атрибуты маршрута сведения о контракте; незатипизированные маршруты `/auth/*` и `/checkout/*` описываются явно; в `Application.kt` включается `encodeDefaults = true`; новая Gradle-задача генерации контрактов. Бизнес-логика и SQL не меняются.
- **`shared`:** не меняется. Он остаётся единственным источником истины для схем.
- **Инфраструктура:** в CI появляется проверка актуальности контрактов; на последней фазе меняются `docker-compose.prod.yaml`, `nginx/prod.conf.template` (`/` → `frontend`), `.github/workflows/docker.yml`, `deploy_to_stand.sh`; `Dockerfile.web` удаляется.
- **Зависимости `web/`:** TanStack Router, Query, Form, Table; zod; Radix/shadcn; `type-coverage`. React Router уходит.
- **Документация:** `CLAUDE.md` (правила TS-кода), `web/README.md`, `DEPLOY.md`.
