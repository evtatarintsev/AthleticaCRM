## Context

- Шапка меню — `Brand` в `web/src/app/AppLayout.tsx`: `Logo` из `ui/AuthLayout.tsx` (буква «A»
  на `bg-primary`) и `me.orgInfo.name`. Рисуется трижды: боковая панель, выезжающее меню,
  верхняя полоса на телефоне.
- Филиал и его смена — `BranchSwitcher` в `app/AccountMenu.tsx`: подменю появляется при двух
  филиалах и больше, список — `myBranchesQuery` (`auth/my-branches`), смена — `useSwitchBranch`
  (перевыпуск токенов, сброс кэша прежнего филиала, перечитывание сессии).
- `auth/my-branches` уже отдаёт только доступные сотруднику филиалы: `DbBranches.list()`
  фильтрует по `ctx.employee.availableBranches`.
- Ассистент — `AssistantHost`: кнопка-триггер в верхней полосе и `EditSheet` с диалогом.
- `components/ui/sheet.tsx` уже умеет `side="bottom"` — шторка для телефона без новых
  зависимостей.

## Goals / Non-Goals

**Goals:**
- Один переключатель филиала — в карточке клуба — на всех ширинах.
- Только веб: не трогать сервер, схемы API, маршрутизацию, права и модель филиалов.

**Non-Goals:**
- Цвет клуба и его выбор в настройках организации — монограмма всегда на `--primary`.
- Права на «Управление филиалами» (отдельное изменение). Пункт «Управление филиалами»
  показывается всем, кому виден список, — так же, как сейчас открыт раздел `/settings/branches`.
- Загрузка логотипа клуба.
- Нижняя панель навигации на телефоне.

## Decisions

### Монограмма — чистая функция в вебе на основном цвете

`monogramOf(name)`: слова по пробелам и дефисам, первые буквы первых двух слов в верхнем
регистре; одно слово — одна буква. Тест на кириллицу, латиницу, кавычки («Олимп»), лишние
пробелы. Сервер монограмму не отдаёт: это вопрос отображения. Квадрат — `bg-primary`,
буквы — `text-primary-foreground`: контраст уже обеспечен темой в обеих схемах.

Цвет клуба отложен: без него изменение не трогает сервер и контракты, а выбор цвета
добавляется позже отдельным изменением без переделки карточки — меняется только класс фона.

### Карточка — один компонент, два способа раскрытия

`ClubCard` получает `me`, список доступных филиалов и режим. Режимы:
`static` (один филиал — `<div>`, без фокуса), `menu` (компьютер — `DropdownMenu` с
`DropdownMenuRadioGroup`), `sheet` (телефон — `Sheet side="bottom"` с `radiogroup`).
Список филиалов загружается тем же `myBranchesQuery`, но сразу при показе раскладки, а не при
открытии меню: от числа филиалов зависит, кнопка ли карточка. Пока список грузится, карточка
показывается статичной.

Альтернатива — общий `DropdownMenu` на телефоне: дешевле, но пункты мелкие и меню прыгает
под край экрана; шторка уже есть в `components/ui`.

### Смена филиала — тот же `useSwitchBranch`

Логика переключения не меняется, меняется место вызова. `BranchSwitcher` удаляется из
`AccountMenu.tsx`, страница `/settings/switch-branch` остаётся как есть.

### Ассистент на телефоне — пункт меню аккаунта

`AssistantHost` разделяется на триггер и панель: панель с состоянием остаётся в раскладке,
открытие поднимается в `open`/`onOpenChange`. На широком экране триггер — кнопка в полосе, на
узком — пункт `DropdownMenuItem` в меню аккаунта; после закрытия панели фокус возвращается на
кнопку меню аккаунта (требование «Панель помощника» в `web-client/ai-assistent` — возврат к
кнопке открытия).

## Risks / Trade-offs

- [Синяя монограмма клуба рядом с синим знаком Athletica внизу меню сливается] → знак продукта
  приглушённый и маленький; при жалобах — сделать его серым, это правка одного класса.
- [`auth/my-branches` теперь грузится на каждой странице] → один короткий запрос на сессию,
  ключ кэша общий с прежним подменю, список меняется редко.
- [Сотрудник ищет смену филиала в меню аккаунта по привычке] → карточка со стрелками — первый
  элемент меню; изменение UI отмечено в описании PR.

## Migration Plan

Только веб: выкатывается обычной сборкой фронтенда, миграций и изменений API нет. Откат —
откат веба.
