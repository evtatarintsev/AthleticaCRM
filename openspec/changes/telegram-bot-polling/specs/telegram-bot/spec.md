## Purpose

Подключение Telegram-бота организации как канала переписки с клиентами. Клиенты пишут боту, сообщения попадают в беседу клиента в CRM, сотрудники отвечают оттуда. Бот работает через опрос Bot API и исходящие прокси, без входящих вебхуков.

## ADDED Requirements

### Requirement: Подключение бота по токену

При создании или изменении Telegram-интеграции система SHALL проверять токен бота запросом к Bot API и сохранять имя пользователя бота. Если токен недействителен, интеграция SHALL не сохраняться, а система SHALL возвращать ошибку `TELEGRAM_TOKEN_INVALID`. Если Bot API недоступен ни через один прокси, интеграция SHALL не сохраняться, а система SHALL возвращать ошибку `TELEGRAM_UNAVAILABLE`.

#### Scenario: Корректный токен

- **WHEN** администратор сохраняет Telegram-интеграцию с действующим токеном
- **THEN** интеграция сохраняется, и в ней записано имя пользователя бота

#### Scenario: Недействительный токен

- **WHEN** администратор сохраняет интеграцию с токеном, который Bot API отклоняет
- **THEN** интеграция не сохраняется, и возвращается ошибка `TELEGRAM_TOKEN_INVALID`

#### Scenario: Bot API недоступен

- **WHEN** ни один прокси из конфигурации не смог выполнить проверку токена
- **THEN** интеграция не сохраняется, и возвращается ошибка `TELEGRAM_UNAVAILABLE`

### Requirement: Один бот — одна интеграция

Токен бота SHALL быть уникален среди всех Telegram-интеграций всех организаций. Если бот с таким токеном уже подключён к другой интеграции, сохранение SHALL отклоняться с ошибкой `TELEGRAM_BOT_IN_USE`.

#### Scenario: Повторное подключение того же бота

- **WHEN** администратор любой организации сохраняет интеграцию с токеном, который уже использует другая интеграция
- **THEN** интеграция не сохраняется, и возвращается ошибка `TELEGRAM_BOT_IN_USE`

### Requirement: Ссылка на бота

Список каналов SHALL отдавать для Telegram-интеграции ссылку `https://t.me/<username>`. Настройки канала в web-клиенте SHALL показывать эту ссылку с возможностью скопировать её.

#### Scenario: Ссылка в настройках

- **WHEN** администратор открывает сохранённую Telegram-интеграцию
- **THEN** он видит ссылку на бота вида `https://t.me/<username>` и может скопировать её

### Requirement: Приём сообщений опросом

Система SHALL получать сообщения каждой включённой Telegram-интеграции опросом Bot API, без входящих вебхуков. Каждое обновление SHALL обрабатываться ровно один раз, в том числе после перезапуска сервера и при нескольких запущенных экземплярах. Обновления отключённой интеграции SHALL не обрабатываться. Включённая или созданная интеграция SHALL начинать опрашиваться без перезапуска сервера.

#### Scenario: Сообщение после перезапуска

- **WHEN** клиент написал боту, пока сервер был остановлен
- **THEN** после запуска сообщение обрабатывается один раз

#### Scenario: Несколько экземпляров сервера

- **WHEN** запущено несколько экземпляров сервера
- **THEN** каждое сообщение клиента попадает в CRM ровно один раз

#### Scenario: Отключённая интеграция

- **WHEN** администратор отключил интеграцию
- **THEN** новые сообщения этому боту не попадают в CRM, пока интеграцию снова не включат

#### Scenario: Новая интеграция

- **WHEN** администратор создал интеграцию с действующим токеном
- **THEN** сообщения боту начинают попадать в CRM без перезапуска сервера

### Requirement: Доступ к Bot API через прокси

Все запросы к Bot API SHALL выполняться через прокси из конфигурации сервера. Поддерживаются HTTP- и SOCKS5-прокси, с аутентификацией и без. Если прокси недоступен, запрос SHALL повторяться через следующий прокси из списка. Если список прокси пуст, запросы SHALL выполняться напрямую. Если запись прокси некорректна (неизвестный тип, нет хоста или порта), сервер SHALL не запускаться.

#### Scenario: Первый прокси недоступен

- **WHEN** первый прокси в списке не отвечает
- **THEN** запрос выполняется через следующий прокси, и сообщение доставляется

#### Scenario: Все прокси недоступны

- **WHEN** ни один прокси не отвечает
- **THEN** опрос повторяется позже, а исходящая доставка считается временным сбоем

#### Scenario: Список прокси пуст

- **WHEN** в конфигурации не задано ни одного прокси
- **THEN** запросы к Bot API выполняются напрямую

### Requirement: Запрос номера телефона

На команду `/start` и на любое сообщение из чата, ещё не привязанного к клиенту, бот SHALL отвечать приветствием с кнопкой «Поделиться номером» (запрос контакта Telegram), пока чат не прислал номер. Номер принимается только если контакт принадлежит самому отправителю. Чужой контакт SHALL игнорироваться для привязки.

#### Scenario: Старт бота

- **WHEN** новый пользователь нажимает «Start» в боте
- **THEN** бот отвечает приветствием с кнопкой «Поделиться номером»

#### Scenario: Пересланный чужой контакт

- **WHEN** пользователь отправляет боту контакт другого человека
- **THEN** номер не используется для привязки, и бот повторно предлагает поделиться своим номером

### Requirement: Автоматическая привязка по номеру

Когда чат присылает свой номер, система SHALL сравнить его с телефонами клиентов организации, без учёта форматирования. Код страны `+7`/`8` для российских номеров считается одинаковым. Если номер совпал ровно с одним клиентом, чат SHALL привязываться к нему, и все ранее накопленные сообщения чата попадают в беседу клиента. Если совпадений нет или их несколько, чат SHALL остаться неразобранным, а присланный номер SHALL сохраниться для ручного разбора. После автоматической привязки бот SHALL подтвердить её клиенту, не раскрывая данных клиента.

#### Scenario: Однозначное совпадение

- **WHEN** чат прислал номер `8 (900) 123-45-67`, а у одного клиента организации есть телефон `+79001234567`
- **THEN** чат привязан к этому клиенту, и его сообщения видны в беседе клиента

#### Scenario: Несколько клиентов с этим номером

- **WHEN** присланный номер есть у двух клиентов организации
- **THEN** чат остаётся в очереди разбора с этим номером, и автоматической привязки нет

#### Scenario: Номер не найден

- **WHEN** присланного номера нет ни у одного клиента организации
- **THEN** чат остаётся в очереди разбора с этим номером

#### Scenario: Клиенты другой организации

- **WHEN** номер совпадает только с клиентом другой организации
- **THEN** привязки нет, и чат остаётся в очереди разбора

### Requirement: Сообщения привязанного чата

Текстовое сообщение из чата, привязанного к клиенту, SHALL попадать в беседу этого клиента как входящее через Telegram-интеграцию. Нетекстовое сообщение (фото, голосовое, видео, стикер, документ и т.п.) SHALL попадать в беседу заглушкой с видом вложения, например «[вложение: фото]». Подпись к вложению SHALL добавляться к заглушке. Сообщения из групп и каналов Telegram SHALL игнорироваться, обрабатываются только личные чаты.

#### Scenario: Текст от привязанного клиента

- **WHEN** привязанный клиент пишет боту «Добрый день, можно перенести занятие?»
- **THEN** в беседе клиента появляется входящее сообщение с этим текстом

#### Scenario: Фото с подписью

- **WHEN** привязанный клиент присылает фото с подписью «справка»
- **THEN** в беседе клиента появляется входящее «[вложение: фото] справка»

#### Scenario: Сообщение из группы

- **WHEN** бота добавили в группу и там пишут сообщения
- **THEN** эти сообщения не попадают в CRM

### Requirement: Ответ сотрудника в Telegram

Сотрудник SHALL иметь возможность отправить сообщение клиенту через Telegram-интеграцию, если у клиента есть привязанный к ней чат. Если привязанного чата нет, отправка SHALL отклоняться с ошибкой `CLIENT_NOT_LINKED`. Временные сбои (сеть, недоступность прокси, ограничение частоты, ошибки сервера Telegram) SHALL повторяться автоматически. Окончательные отказы (бот заблокирован клиентом, чат не найден) SHALL переводить доставку в состояние «не доставлено» с причиной и без повторов.

#### Scenario: Успешная отправка

- **WHEN** сотрудник отвечает привязанному клиенту через Telegram
- **THEN** клиент получает сообщение от бота, а доставка в беседе отмечена отправленной

#### Scenario: Клиент заблокировал бота

- **WHEN** Telegram отклоняет отправку, потому что пользователь заблокировал бота
- **THEN** доставка отмечается «не доставлено» с причиной, повторов нет

#### Scenario: Ограничение частоты

- **WHEN** Telegram отвечает ограничением частоты запросов
- **THEN** доставка остаётся ожидающей и повторяется позже

#### Scenario: Клиент без чата

- **WHEN** сотрудник пытается отправить через Telegram клиенту без привязанного чата
- **THEN** отправка отклоняется с ошибкой `CLIENT_NOT_LINKED`
