# Proposal

## Why

Блок «Контакты» на форме клиента формально верен, но тяжёл: в каждой строке селект типа и поле, а
кнопка «Добавить» всегда создаёт телефон, который потом приходится переключать. При этом реальная
потребность другая: у ребёнка несколько телефонов (мама, папа, бабушка), и нужно понимать, чей это
номер и на какой из них слать SMS. Сейчас «основной» телефон — просто первый по порядку, а подписи
у номера нет.

## What Changes

- У каждого контакта появляются свободный комментарий (`label`, например «мама») и флаг «основной»
  (`isPrimary`). Модель одинакова для всех типов; типы PHONE, EMAIL, TELEGRAM, VK, FACEBOOK остаются.
- Основной выбирается внутри типа: у клиента не больше одного основного контакта каждого типа. Если
  в типе нет отмеченного основного, основным становится первый контакт этого типа; два основных
  одного типа — ошибка.
- Форма клиента: строка контакта — иконка типа, значение, комментарий, флажок «основной» (только
  когда контактов этого типа больше одного), удаление. Тип после создания строки не меняется —
  селекта типа нет. Добавление — кнопки «+ Телефон», «+ Email» и меню «+ Ещё» с Telegram, VK, Facebook.
- Списки контактов (карточка клиента, панель участника занятия) показывают значение и комментарий;
  основной контакт типа идёт первым.
- Шапка карточки клиента показывает основной телефон, а не первый.
- В панели «Чат» адрес получателя по умолчанию — основной контакт нужного каналу типа (SMS — на
  основной телефон).
- Помощник передаёт комментарий к контакту («телефон мамы» → «мама») и показывает его в карточке
  подтверждения; основной — если пользователь его назвал, иначе по общему правилу.
- API: `ClientContactInput` и `ClientContactSchema` получают поля `label` и `isPrimary`
  (новые поля необязательны во входе — старые клиенты API не ломаются).

## Capabilities

### New Capabilities

- `client-contacts`: модель контакта клиента на сервере — тип, значение, комментарий, основной
  контакт внутри типа и правило его выбора при замене набора контактов.
- `web-client/client-contacts`: редактор контактов на форме клиента и общий список контактов со
  ссылками, комментарием и порядком «основной первым».

### Modified Capabilities

- `web-client/client-detail`: шапка показывает основной телефон вместо первого; карточка «Контакты»
  показывает комментарий к контакту.
- `web-client/client-chat`: адрес-получатель по умолчанию — основной контакт.

## Impact

- БД: новая миграция `client_contacts` — колонки `label`, `is_primary`, `position`, частичный
  уникальный индекс и отложенный триггер «ровно один основной в типе».
- `shared`: `ClientContactSchemas.kt`; регенерация `web/src/api/generated/contracts.ts`.
- `server`: `domain/clientcontacts` (`ClientContact`, `DbClientContacts.replace`), `ClientsRoutes`,
  `read/clients/DbClientListView`, `read/messaging/DbClientChannelsView`, детальная проекция
  клиента, `assistant/tools/ClientDrafts`.
- `web`: `ClientContactsFields.tsx`, `clientContacts.ts`, `card/ClientContactList.tsx`,
  `card/ClientCardHeader.tsx`, `messaging/ConversationThread.tsx`, словари `ru.ts`/`en.ts`.
- Связанный change `client-mobile-app`: в списке доступов к приложению показывать комментарий к
  номеру («мама — подключён»).
