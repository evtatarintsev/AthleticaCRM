# Spec Delta

## MODIFIED Requirements

### Requirement: Иерархия административных команд

Административные операции SHALL быть сгруппированы под подкомандой `admin`, отделяющей операции над данными от режимов запуска приложения. Операции над организациями SHALL находиться в группе `admin org`. Операции над пользователями SHALL находиться в группе `admin user`, поскольку пользователь не принадлежит одной организации.

#### Scenario: Справка по уровню вложенности

- **WHEN** запрошена справка для `admin`, `admin org` или `admin user`
- **THEN** выводится список подкоманд соответствующего уровня с их описаниями

#### Scenario: Неизвестная подкоманда

- **WHEN** указана несуществующая подкоманда
- **THEN** выводится сообщение об ошибке в поток ошибок, приложение завершается с ненулевым кодом возврата, никаких изменений в данных не происходит

## ADDED Requirements

### Requirement: Сброс пароля пользователя

Команда `admin user reset-password` SHALL принимать логин пользователя и заменять его пароль новым, не требуя старого пароля. Пользователь SHALL определяться по точному совпадению логина, без указания организации. После сброса пользователь SHALL входить с новым паролем, а старый пароль SHALL перестать подходить для входа.

#### Scenario: Пароль сброшен

- **WHEN** выполняется `admin user reset-password` с логином существующего пользователя и вводится новый пароль
- **THEN** пароль пользователя заменяется новым, вход с новым паролем проходит, вход со старым паролем отклоняется, и выводится сообщение об успешной смене пароля с логином пользователя

#### Scenario: Пользователь не найден

- **WHEN** логин не соответствует ни одному пользователю
- **THEN** выводится сообщение об ошибке в поток ошибок, приложение завершается с ненулевым кодом возврата, пароли пользователей не изменяются

#### Scenario: Пользователь — сотрудник нескольких организаций

- **WHEN** сбрасывается пароль пользователя, который является сотрудником нескольких организаций
- **THEN** новый пароль действует для входа во все эти организации

### Requirement: Новый пароль вводится только интерактивно

Новый пароль SHALL запрашиваться у администратора после запуска команды и не SHALL приниматься аргументом или опцией командной строки. Ввод SHALL быть скрыт и SHALL запрашиваться дважды для подтверждения. Новый пароль не SHALL выводиться ни в стандартный поток вывода, ни в поток ошибок.

#### Scenario: Пароль нельзя передать в командной строке

- **WHEN** `admin user reset-password` вызвана с лишним аргументом или опцией, через которые можно было бы передать пароль
- **THEN** выводится ошибка разбора аргументов, приложение завершается с ненулевым кодом возврата, подключение к базе данных не открывается и пароль не изменяется

#### Scenario: Вывод не содержит пароля

- **WHEN** пароль успешно сброшен
- **THEN** ни стандартный поток вывода, ни поток ошибок не содержат введённого пароля

### Requirement: Отклонение недопустимого ввода пароля

Команда сброса пароля SHALL отклонять пустой пароль и пароль, два ввода которого не совпадают. В обоих случаях пароль пользователя SHALL оставаться прежним, а приложение SHALL завершаться с ненулевым кодом возврата.

#### Scenario: Пустой пароль

- **WHEN** в ответ на запрос нового пароля введена пустая строка
- **THEN** выводится сообщение об ошибке в поток ошибок, приложение завершается с ненулевым кодом возврата, пароль пользователя не изменяется

#### Scenario: Вводы не совпадают

- **WHEN** пароль и его подтверждение различаются
- **THEN** выводится сообщение об ошибке в поток ошибок, приложение завершается с ненулевым кодом возврата, пароль пользователя не изменяется
