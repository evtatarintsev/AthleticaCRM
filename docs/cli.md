# Командная строка приложения

Приложение поставляется одним исполняемым артефактом `athletica.jar`, который выбирает
режим работы по подкоманде: либо поднимает веб-сервер, либо выполняет административные
операции над данными.

```
athletica serve
athletica admin org find <запрос>...
athletica admin org credit <организация> <сумма> --description=<описание>
athletica admin org debit  <организация> <сумма> --description=<описание>
```

Справка доступна на каждом уровне: `athletica --help`, `athletica admin --help`,
`athletica admin org --help`. Для справки и разбора аргументов подключение к базе данных
не открывается.

## Запуск

### В продакшене

Административные команды выполняются внутри контейнера сервера — там уже есть и сеть до
базы данных, и переменные окружения:

```bash
docker compose -f docker-compose.prod.yaml exec server java -jar athletica.jar admin org find ЦР
```

Веб-сервер запускается образом по умолчанию (`CMD ["serve"]`), поэтому
`docker-compose.prod.yaml` не задаёт `command:`.

### Локально

```bash
./gradlew :server:shadowJar
java -jar server/build/libs/athletica.jar admin org find ЦР
```

Веб-сервер локально удобнее запускать через Gradle:

```bash
./gradlew :server:run --args="serve"
```

### Переменные окружения

Административным командам нужны те же параметры подключения к базе данных, что и серверу:

- `POSTGRES_URL` — JDBC URL подключения (например, `jdbc:postgresql://localhost:5432/athletica`)
- `POSTGRES_USER` — имя пользователя
- `POSTGRES_PASSWORD` — пароль

Остальные переменные окружения сервера (`JWT_SECRET`, `MINIO_*`, `SMTP_*`, `YOOKASSA_*`)
административным командам не требуются.

## Команды

### `serve` — веб-сервер

Поднимает HTTP-сервер: применяет миграции базы данных и стартует фоновые процессы.
Собственных опций не имеет — конфигурация читается из `application.conf` и переменных
окружения.

### `admin org find` — поиск организаций

Поиск по вхождению подстроки в название организации или в логин её владельца. Принимает
один или несколько запросов; неудача одного запроса не прерывает обработку остальных.

```bash
athletica admin org find ЦР
athletica admin org find ЦР admin
```

Вывод:

```
Результаты для "ЦР":
  019e1c25-7d23-7234-9ef8-160057bc67e4  ЦРФКС  (владелец: admin, валюта: RUB)
```

Если ничего не найдено, печатается сообщение об отсутствии результатов, код возврата
остаётся нулевым.

### `admin org credit` и `admin org debit` — корректировка баланса организации

```bash
athletica admin org credit <организация> <сумма> --description=<описание>
athletica admin org debit  <организация> <сумма> --description=<описание>
```

Аргументы:

- `<организация>` — UUID организации либо её название. Если названию соответствует
  несколько организаций, операция отклоняется, а список подходящих организаций с их
  идентификаторами выводится в поток ошибок.
- `<сумма>` — величина корректировки в основных единицах валюты организации (рубли,
  доллары и т.д.). Валюта операции определяется валютой организации и в командной строке
  не задаётся.
- `--description` — описание операции; обязательно. Вызов без описания отклоняется на
  этапе разбора аргументов, до обращения к базе данных.

Примеры:

```bash
athletica admin org credit ЦРФКС 1000 --description="Тестовое зачисление"
athletica admin org debit 019e1c25-7d23-7234-9ef8-160057bc67e4 500 --description="Возврат средств"
```

Вывод:

```
Организация: ЦРФКС (019e1c25-7d23-7234-9ef8-160057bc67e4)
Корректировка: +1 000,00 ₽
Новый баланс:  15 000,00 ₽
```

## Вывод и коды возврата

Вывод рассчитан на чтение человеком и не является контрактом для скриптов: машиночитаемого
режима нет. Денежные суммы печатаются в формате валюты организации. Результаты идут в
стандартный поток вывода, сообщения об ошибках — в поток ошибок.

Ненулевой код возврата означает, что операция не выполнена: неизвестная подкоманда,
отсутствующее `--description`, ненайденная или неоднозначно указанная организация,
незаданные переменные окружения с параметрами подключения к базе данных.

## Требования

- Java 17+ (базовый образ `Dockerfile.server` — `eclipse-temurin:17`)
- PostgreSQL с базой данных AthleticaCRM
