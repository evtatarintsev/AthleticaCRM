# Spec Delta

## Purpose

Определяет составную серверную сортировку списка клиентов, совместимость существующих запросов и отдельный порядок ближайших дней рождения без изменения сортировки по полной дате рождения.

## ADDED Requirements

### Requirement: Упорядоченный список критериев сортировки клиентов

API `clients/list` SHALL принимать необязательный массив `sort` из критериев `{ field, direction }`. Порядок элементов SHALL задавать приоритет: следующий критерий применяется при равенстве предыдущих. Допустимые поля — `NAME`, `BALANCE`, `BIRTHDAY`, `NEXT_BIRTHDAY`; направления — `Asc` и `Desc`, по умолчанию `Asc`. Непустой массив SHALL иметь приоритет над одиночными `sortField` и `sortDirection`.

#### Scenario: День рождения и имя
- **WHEN** запрос задаёт `sort = [{ field: NEXT_BIRTHDAY, direction: Asc }, { field: NAME, direction: Asc }]` и диапазон дней рождения от сегодняшней даты
- **THEN** клиенты расположены по близости дня рождения, а внутри одного месяца и дня — по имени независимо от года рождения

#### Scenario: Независимые направления
- **WHEN** запрос задаёт `BALANCE Desc`, затем `NAME Asc`
- **THEN** клиенты расположены по убыванию баланса, а при одинаковом балансе — по имени по возрастанию

#### Scenario: Приоритет нового формата
- **WHEN** запрос содержит `sortField = NAME`, `sortDirection = Desc` и непустой массив `sort = [{ field: BALANCE, direction: Asc }]`
- **THEN** применяется только порядок массива, по балансу по возрастанию

### Requirement: Совместимость одиночной сортировки

Если `sort` отсутствует, равен null или пуст, API SHALL применять существующие `sortField` и `sortDirection` с прежними значениями по умолчанию. `BIRTHDAY` SHALL продолжать сравнивать полную дату рождения, включая год. Изменение SHALL NOT требовать миграции сохранённых настроек сортировки других списков.

#### Scenario: Старый запрос
- **WHEN** запрос содержит только `sortField = BIRTHDAY` и `sortDirection = Asc`
- **THEN** клиент с датой рождения 1990-12-31 предшествует клиенту с датой 2000-01-01

#### Scenario: Пустой новый массив
- **WHEN** запрос содержит `sort = []`, `sortField = NAME`, `sortDirection = Desc`
- **THEN** применяется сортировка по имени по убыванию

#### Scenario: Запрос без сортировки
- **WHEN** запрос не задаёт ни новый массив, ни старые поля сортировки
- **THEN** применяется прежний порядок по имени по возрастанию

### Requirement: Ближайший день рождения относительно начала диапазона

`NEXT_BIRTHDAY` SHALL сравнивать месяц и день рождения циклически относительно `birthday.from`, не учитывая год рождения и часы сервера. По возрастанию сначала SHALL идти дата начала диапазона, затем следующие месяц и день, включая переход через Новый год. Этот критерий SHALL требовать непустой фильтр `birthday`. Отбор SHALL сохранять существующее точное сравнение месяца и дня без переноса 29 февраля на другую дату.

#### Scenario: Переход через Новый год
- **WHEN** диапазон — 2026-12-30…2027-01-06 и даты рождения клиентов — 1990-12-30, 2010-12-31, 1980-01-01
- **THEN** сортировка `NEXT_BIRTHDAY Asc` возвращает их в порядке 30 декабря, 31 декабря, 1 января

#### Scenario: Убывание близости
- **WHEN** в том же диапазоне выбран `NEXT_BIRTHDAY Desc`
- **THEN** порядок дат — 1 января, 31 декабря, 30 декабря

#### Scenario: Дата браузера отличается от даты сервера
- **WHEN** начало диапазона клиента — 2026-11-18, а сервер уже считает текущей датой 2026-11-19
- **THEN** ближайшим считается 18 ноября согласно переданному диапазону

#### Scenario: 29 февраля
- **WHEN** диапазон — 2028-02-28…2028-03-01 и есть клиенты с днями рождения 28 февраля, 29 февраля и 1 марта
- **THEN** они возвращаются в указанном календарном порядке
- **AND** диапазон только за 1 марта 2027 года не включает клиента с днём рождения 29 февраля

### Requirement: Порядок применяется до ограничения страницы

Система SHALL применять все критерии сортировки до `limit` и `offset`, оставлять null после непустых значений при любом направлении и завершать порядок идентификатором клиента по возрастанию. `total` SHALL считать все совпадения фильтра независимо от сортировки и размера страницы.

#### Scenario: Сегодняшние именинники за пределами алфавитного лимита
- **WHEN** в диапазоне 12 клиентов, лимит 2, у Яны день рождения сегодня, а у Анны и Бориса завтра
- **THEN** при сортировке `NEXT_BIRTHDAY Asc`, `NAME Asc` первая страница содержит Яну и Анну, а `total` равен 12

#### Scenario: Полностью совпавшие критерии
- **WHEN** у нескольких клиентов одинаковые месяц и день рождения и имя, а страницы запрашиваются с последовательными смещениями на неизменном наборе данных
- **THEN** их взаимный порядок определяется идентификатором и страницы не дублируют и не пропускают клиентов

#### Scenario: Отсутствующая дата рождения
- **WHEN** список без фильтра дней рождения сортируется по `BIRTHDAY Desc`, затем `NAME Asc`
- **THEN** клиенты без даты рождения расположены после клиентов с датой, между собой — по имени

### Requirement: Некорректная сортировка отклоняется

API SHALL отклонять с ответом 400 неизвестные поля или направления, повторение поля в непустом массиве и `NEXT_BIRTHDAY` без фильтра `birthday`, в том числе в одиночном формате. Значения запроса SHALL NOT интерпретироваться как произвольные выражения сортировки.

#### Scenario: Повторённое поле
- **WHEN** `sort` содержит два критерия `NAME` с любыми направлениями
- **THEN** API возвращает 400

#### Scenario: Нет опорной даты
- **WHEN** эффективная сортировка содержит `NEXT_BIRTHDAY`, а фильтр `birthday` отсутствует
- **THEN** API возвращает 400

#### Scenario: Неизвестный критерий
- **WHEN** запрос содержит неизвестное поле или направление сортировки
- **THEN** API возвращает 400 и не выполняет переданное значение как выражение сортировки
