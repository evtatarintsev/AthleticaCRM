# client-cabinet-web Specification

## Purpose

Веб-кабинет клиента организации: где он открывается, как хранится сеанс в браузере, как выглядит на телефоне и каким контрактом API пользуется. Поведение, общее с мобильными приложениями, описано в `client-app-access` и `client-app-overview`.

## Requirements

### Requirement: Отдельный адрес кабинета

Кабинет SHALL открываться на поддомене `clients` основного домена платформы. На этом адресе SHALL быть доступны только страницы кабинета и клиентское API. Маршруты API CRM SHALL NOT отвечать на адресе кабинета.

#### Scenario: Вход в кабинет

- **WHEN** человек открывает `https://clients.<домен>`
- **THEN** он видит страницу входа по номеру телефона

#### Scenario: API CRM с адреса кабинета

- **WHEN** на `https://clients.<домен>` отправлен запрос к маршруту API CRM
- **THEN** запрос не доходит до сервера, ответ — «не найдено»

### Requirement: Сеанс кабинета в браузере

Сеанс SHALL храниться в браузере так, чтобы скрипты страницы не могли его прочитать. Сеанс кабинета и сеанс CRM SHALL быть независимы: вход или выход в одном не влияет на другой, даже в одном браузере. Сеанс SHALL показываться в списке сеансов аккаунта с названием браузера и системы.

#### Scenario: Сотрудник и родитель в одном браузере

- **WHEN** администратор вошёл в CRM, а затем в том же браузере открыл кабинет
- **THEN** кабинет просит войти по номеру телефона, вход в CRM при этом сохраняется

#### Scenario: Сеанс в списке

- **WHEN** мама вошла в кабинет с Safari на iPhone
- **THEN** в списке сеансов есть строка «Safari, iOS» с датой последней активности

### Requirement: Кабинет под экран телефона

Каждый экран кабинета SHALL быть пригоден к работе на ширине экрана от 360 px без горизонтальной прокрутки. На широком экране SHALL показываться та же раскладка, ограниченная по ширине.

#### Scenario: Узкий экран

- **WHEN** расписание открыто на экране шириной 360 px
- **THEN** все занятия недели и кнопка «Не придём» доступны без горизонтальной прокрутки

### Requirement: Кабинет закрыт от индексации и встраивания

Страницы кабинета SHALL запрещать индексацию поисковиками и встраивание в чужие сайты.

#### Scenario: Встраивание во фрейм

- **WHEN** сторонний сайт пытается открыть кабинет во фрейме
- **THEN** браузер отказывается показывать страницу

### Requirement: Контракт API кабинета

Контракт API кабинета SHALL строиться автоматически из маршрутов клиентского API сервера так же, как контракт CRM, и SHALL содержать только эти маршруты. Контракт CRM SHALL NOT содержать маршрутов клиентского API. CI SHALL проверять, что оба сгенерированных контракта не устарели.

#### Scenario: Новый маршрут клиентского API

- **WHEN** на сервере зарегистрирован новый маршрут клиентского API, и контракты перегенерированы
- **THEN** маршрут появляется в контракте кабинета и отсутствует в контракте CRM

#### Scenario: Забыли перегенерировать

- **WHEN** в PR изменена схема клиентского API, а контракт кабинета не обновлён
- **THEN** проверка CI падает и сообщает, что контракты устарели
