## Why

Сейчас клиент (чаще родитель ребёнка) узнаёт о расписании, остатке абонемента и долге только
от администратора — в мессенджере или на ресепшене. Это нагружает администраторов и не даёт
клиенту самому оплатить или предупредить о пропуске. Нужно одно мобильное приложение
«Athletica» для клиентов всех организаций, в которое клиент входит без пароля и где видит
только свои данные. Главный риск — администратор ошибся в номере телефона, и посторонний
получает доступ к персональным данным ребёнка (152-ФЗ); защита от этого — часть требований,
а не доработка «на потом».

## What Changes

- Организация включает клиентское приложение в настройках и приглашает клиентов — по одному
  из карточки или всех сразу. Без приглашения войти нельзя.
- Вход по номеру телефона и одноразовому коду (Telegram, запасной канал — SMS). Паролей нет:
  нет ни выдачи первого пароля, ни восстановления.
- Один номер — один аккаунт. В аккаунте все клиенты всех организаций, у которых записан этот
  номер (родитель видит всех своих детей). Организации друг о друге не узнают.
- Подключение к организации подтверждается датой рождения **каждого** клиента отдельно;
  клиента без даты рождения подключить нельзя, пока администратор её не заполнит. До
  подтверждения человек видит только название организации. Три неверные даты подряд —
  блокировка на всех устройствах и задача администратору «проверьте номер». Кнопка «Это не я»
  сообщает об ошибке в номере. Та же проверка — на новом устройстве.
- Доступ закрывается сразу, если номер удалён из карточки, клиент архивирован, приложение
  в организации выключено или сотрудник отключил доступ. Закрытие доступа в одной организации
  не трогает сеансы и доступы в других.
- Человек может удалить аккаунт в приложении.
- В карточке клиента CRM — статус приложения по каждому номеру, кнопки «Пригласить»,
  «Напомнить», «Отключить», «Разблокировать».
- В приложении: главная, расписание с отметкой «Не придём», история посещений, абонементы,
  баланс и его история, онлайн-оплата (пополнение баланса и покупка того же абонемента), переписка
  с клубом с push-уведомлениями, список устройств и выход.
- Оплата идёт на счёт самой организации через её магазин ЮKassa, подключённый в настройках,
  с чеком по 54-ФЗ от ЮKassa. В учёте это обычная оплата клиента в онлайн-кассу организации
  по главной книге: пополнение аванса, а при покупке абонемента — ещё и продажа, оплаченная
  с аванса. Видна в истории баланса, кассовом журнале и ДДС.
- Новое мобильное приложение для iOS и Android в репозитории.
- **Не входит**: магазин товаров, самостоятельная запись на разовые занятия, брендированные
  приложения клубов, вход по email, вход сотрудников через это приложение, подключение по
  QR-коду на месте.

## Capabilities

### New Capabilities
- `client-app-access`: приглашения, вход по коду, аккаунт по номеру, подтверждение личности
  датой рождения, блокировка и «Это не я», устройства, отзыв доступа, изоляция организаций,
  удаление аккаунта.
- `client-app-admin`: включение приложения в организации, массовое и единичное приглашение,
  статусы доступа в карточке клиента, задачи по ошибкам в номере.
- `client-app-overview`: что клиент видит в приложении — главная, расписание, посещения,
  абонементы, баланс, переключение между клиентами и организациями.
- `client-app-payments`: подключение ЮKassa организации (касса, налоговые настройки чека),
  онлайн-пополнение баланса, покупка того же абонемента оплатой в приложении.
- `client-app-chat`: переписка клиента с организацией из приложения как канал единых
  «Входящих», push-уведомления о новых сообщениях.

### Modified Capabilities
- `attendance-journal`: клиент может заранее предупредить об отсутствии; предупреждение видно
  сотруднику в журнале занятия, отметку по-прежнему ставит сотрудник.
- `client-payments`: оплата из приложения записывается по общим правилам, без автора-сотрудника,
  с отметкой «из приложения».

## Impact

- **mobile** (новый модуль): приложение на Kotlin Multiplatform + Compose Multiplatform для
  Android и iOS, использует схемы из `shared`. Публикация в App Store, Google Play, RuStore.
- **server**: новый контур аутентификации клиентов (отдельный JWT-аудиенс, контексты
  `ClientAccountContext`/`ClientProfileContext` вне `RequestContext`), домены `clientapp` (аккаунты, доступы, устройства, коды),
  проекции `read/clientapp/*`, маршруты `/client-app/*` и `/client-app-admin/*`, вебхук ЮKassa
  для платежей клиентов, отправка кодов (Telegram Gateway, SMS) и push (FCM, APNs).
- **shared**: схемы запросов и ответов клиентского API, `ClientAppAccessStatus`, новое право
  `CAN_MANAGE_CLIENT_APP`.
- **web**: блок «Мобильное приложение» в карточке клиента, страница настроек «Клиентское
  приложение», подключение ЮKassa, предупреждения об отсутствии в журнале; перегенерация
  `web/src/api/generated/`.
- **БД**: новые таблицы аккаунтов, доступов, устройств, кодов, проверок, платежей клиентов,
  магазинов ЮKassa организаций, предупреждений об отсутствии. Главная книга не меняется:
  оплаты пишутся существующими шаблонами проводок.
- **Конфигурация**: ключи Telegram Gateway, SMS-провайдера, FCM, APNs — в `application.conf`,
  `docker-compose.prod.yaml`, `.env.prod.example`. Мобильные таргеты Gradle — за свойством
  `athletica.mobile`, серверная Docker-сборка и CI не требуют Android SDK.
- **Внешние зависимости**: Telegram Gateway API, SMS-провайдер платформы, Firebase Cloud
  Messaging, Apple Push Notification service, ЮKassa (магазины организаций).
