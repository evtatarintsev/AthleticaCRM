## Why

В списке клиентов не видно абонементов: чтобы узнать, какой абонемент у клиента, сколько занятий
осталось и до какого числа он действует, администратор открывает карточку каждого клиента. Так же
не видно неоплаченных занятий — долг по занятиям виден только в карточке и в составе группы.

Из вариантов, разобранных с заказчиком (основной абонемент с «+N», все абонементы чипами, только
статус, отдельные колонки «Абонемент / Занятий / До», полоска остатка, общая колонка «Группы и
абонементы»), выбран вариант **«группы и абонементы — две колонки, строчка на группу»**: каждая группа
клиента стоит на своей строчке, а абонемент этой группы — в соседней колонке на той же высоте.

Макет: `mockups/clients-list-memberships.html` (компьютер и телефон — одна адаптивная страница;
переключатель «Компьютер / Телефон» сверху — только для макета).

## What Changes

- Новая колонка таблицы «Абонемент»: для каждой группы клиента — метка абонемента этой группы на той же
  строчке, что и группа:
  - «8 из 12 · до 03.12», «Безлимит · до 30.11» — действует;
  - «Заканчивается · 1 из 8» (или «· до 22.11») — заканчивается;
  - «К закрытию · срок вышел» / «К закрытию · занятия закончились»;
  - «Начнётся 01.12», «С первого посещения» — ещё не начался;
  - «Нет абонемента».
- Колонка «Группы» показывает все группы клиента чипами друг под другом вместо «не больше двух и
  "+N"».
- Под именем клиента всегда показываются пол и возраст («Ж · 9 лет»). Пол и дата рождения перестают
  быть колонками таблицы.
- Под балансом — число неоплаченных занятий клиента («2 неоплач.»), если они есть.
- Колонки по умолчанию — «Группы», «Абонемент», «Баланс»; каждую можно выключить в «Колонках».
  Контакты и дополнительные поля по-прежнему добавляются через «Колонки».
- Сохранённые настройки колонок переносятся: у кого сохранён прежний набор по умолчанию, тот получает
  новый; у остальных из набора убираются пол и дата рождения.
- Сортировки по дате рождения в списке больше нет; сохранённая сортировка по дате рождения заменяется
  сортировкой по имени.
- Телефон: строка клиента — имя, «Ж · 9 лет», баланс с неоплаченными справа и под ними блок «группа —
  абонемент» на приглушённой подложке. Блок и баланс подчиняются тем же настройкам колонок.
- API `clients/list` отдаёт для клиента абонемент каждой его группы с признаками на сегодня и число
  неоплаченных занятий.
- Экспорт CSV, фильтры, виды, поиск и сортировки API — без изменений; абонементы в экспорт не входят.
- **BREAKING**: нет. Пол и дата рождения уходят из колонок таблицы, но остаются под именем и в экспорте.

## Capabilities

### New Capabilities

- `client-list`: данные строки списка клиентов в API — абонементы по группам клиента с признаками
  на сегодня и число неоплаченных занятий.

### Modified Capabilities

- `web-client/clients-list`: вид строки на компьютере и телефоне (пол и возраст под именем, группы
  друг под другом, колонка «Абонемент», неоплаченные под балансом), набор колонок по умолчанию,
  перенос сохранённых настроек, отказ от сортировки по дате рождения.

## Impact

- `shared`: схема элемента списка клиентов (абонементы по группам, число неоплаченных занятий);
  каталог колонок таблицы отделяется от каталога полей экспорта `ClientField`.
- `server`: проекция `DbClientListView` (абонемент группы по ступеням, как в составе группы; признаки
  через общий `ActiveStatus`; «сегодня» — из запроса); маршрут `clients/list` передаёт текущий момент;
  миграция Liquibase сохранённых настроек колонок; значения по умолчанию `ClientsDisplaySettings`.
- `web`: `ClientListTable`, `clientColumns`, `ClientColumnsDialog`, сортировка в `clientListSearch`;
  словари `ru`/`en`; перегенерация `web/src/api/generated/`.
