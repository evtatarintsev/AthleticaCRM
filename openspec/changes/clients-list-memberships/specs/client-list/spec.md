# Spec Delta

## Purpose

Данные строки списка клиентов в API `clients/list`: что сервер отдаёт о клиенте помимо карточных
полей — абонементы по группам клиента с признаками на сегодня и долг по занятиям.

## ADDED Requirements

### Requirement: Абонемент каждой группы клиента в списке
Для каждой текущей группы клиента элемент списка SHALL содержать абонемент этой группы или его
отсутствие. Абонемент группы SHALL выбираться среди неактивированных и активных абонементов клиента,
действующих в этой группе, по тем же ступеням, что и в составе группы (`group-roster`): сначала
активный не «к закрытию», затем активный «к закрытию», затем неактивированный.

#### Scenario: Две группы с разными абонементами
- **WHEN** клиент состоит в группах «Мини» и «Юниор», в «Мини» действует абонемент «Мини 8», в «Юниор» — безлимит
- **THEN** элемент списка содержит для «Мини» абонемент «Мини 8», для «Юниор» — безлимит

#### Scenario: Группа без абонемента
- **WHEN** клиент состоит в группах «Старшая» и «ОФП взрослые», абонемент есть только в «Старшая»
- **THEN** для «ОФП взрослые» в элементе списка абонемента нет

#### Scenario: Закрытый и отозванный абонемент не показываются
- **WHEN** единственный абонемент клиента в группе закрыт или отозван
- **THEN** для этой группы в элементе списка абонемента нет

#### Scenario: Действующий абонемент важнее будущего
- **WHEN** в группе у клиента активный абонемент в сроке и неактивированный абонемент на следующий месяц
- **THEN** для группы отдаётся активный абонемент

### Requirement: Признаки абонемента в списке вычисляет сервер
Для абонемента группы SHALL отдаваться название, сохранённое состояние, лимит и остаток занятий,
даты начала и окончания, режим активации, а для активного — признаки на сегодня по
`membership-lifecycle`: положение относительно срока, причины «заканчивается» и «к закрытию».
«Сегодня» SHALL определяться в часовом поясе организации на момент запроса. Веб-клиент SHALL NOT
вычислять эти признаки сам.

#### Scenario: Заканчивается по занятиям
- **WHEN** у активного абонемента в сроке остаток 1 из 8
- **THEN** абонемент отдаётся с причиной «заканчивается» по занятиям

#### Scenario: Срок вышел
- **WHEN** сегодня 20.11, у активного абонемента дата окончания 15.11 и остаток 2
- **THEN** абонемент отдаётся с признаком «к закрытию» и положением «срок вышел»

### Requirement: Число неоплаченных занятий клиента в списке
Элемент списка SHALL содержать число неоплаченных занятий клиента во всех группах организации —
по тому же определению, что и список неоплаченных занятий (`client-unpaid-sessions`). У клиента без
неоплаченных занятий число SHALL быть равно 0.

#### Scenario: Неоплаченные в разных группах
- **WHEN** у клиента неоплаченное занятие в группе «Мини» и разовое неоплаченное посещение группы, в которой он не состоит
- **THEN** число неоплаченных занятий в элементе списка равно 2

#### Scenario: Сторнированное списание
- **WHEN** единственное списание за проведённое занятие с отметкой «пришёл» сторнировано
- **THEN** занятие входит в число неоплаченных

### Requirement: Данные списка собираются в пределах страницы
Абонементы групп и число неоплаченных занятий SHALL собираться тем же запросом страницы списка в
пределах организации текущего сотрудника, не меняя фильтрацию, сортировку, пагинацию и `total`.

#### Scenario: Пагинация не меняется
- **WHEN** список из 120 клиентов запрашивается страницами по 50
- **THEN** `total` равен 120, а у каждого клиента страницы есть абонементы его групп и число неоплаченных занятий
