## Purpose

Правила вычисления действующих прав сотрудника организации: права из ролей, персональные выдачи
и отзывы, а также особый статус владельца организации, у которого есть все права.

## ADDED Requirements

### Requirement: Действующие права обычного сотрудника

Для сотрудника, не являющегося владельцем организации, право SHALL считаться выданным, если оно
выдано сотруднику персонально или входит хотя бы в одну из его ролей, и при этом не отозвано
у него персонально. Персональный отзыв SHALL иметь приоритет над ролями и персональной выдачей.

#### Scenario: Право из роли

- **WHEN** сотруднику назначена роль с правом просмотра баланса клиента и это право у него не отозвано
- **THEN** проверка права просмотра баланса клиента для этого сотрудника проходит

#### Scenario: Персональный отзыв сильнее роли

- **WHEN** сотруднику назначена роль с правом просмотра баланса клиента, но это право отозвано у него персонально
- **THEN** проверка права просмотра баланса клиента для этого сотрудника не проходит

#### Scenario: Нет ни роли, ни выдачи

- **WHEN** у сотрудника нет ролей и персональных выдач
- **THEN** ни одна проверка пользовательского права для него не проходит

### Requirement: Владелец организации имеет все права

Владелец организации SHALL проходить проверку любого пользовательского права, включая права,
добавленные в систему позже, независимо от назначенных ему ролей, персональных выдач и отзывов.
Персональные отзывы у владельца SHALL не действовать. Правило SHALL применяться при каждом
запросе владельца, без повторного входа.

#### Scenario: Владелец без ролей

- **WHEN** владелец организации без ролей и персональных выдач запрашивает журнал баланса клиента
  или список всех задач
- **THEN** проверки прав просмотра баланса клиента и просмотра всех задач для него проходят

#### Scenario: Отзыв у владельца не действует

- **WHEN** у владельца организации персонально отозвано право управления задачами
- **THEN** проверка права управления задачами для владельца всё равно проходит

#### Scenario: Обычный сотрудник не затронут

- **WHEN** сотрудник, не являющийся владельцем, не имеет права просмотра всех задач
- **THEN** проверка этого права для него не проходит, как и до изменения

### Requirement: Сессия владельца сообщает полный набор прав

Ответ на запрос текущей сессии SHALL содержать в списке прав владельца организации все
пользовательские права системы. Для остальных сотрудников список SHALL содержать ровно те права,
проверка которых для них проходит.

#### Scenario: Сессия владельца

- **WHEN** владелец организации без ролей запрашивает текущую сессию
- **THEN** список прав в ответе содержит все пользовательские права системы

#### Scenario: Сессия сотрудника с одной ролью

- **WHEN** сотрудник, не являющийся владельцем, с единственной ролью, дающей право просмотра
  баланса клиента, запрашивает текущую сессию
- **THEN** список прав в ответе содержит только право просмотра баланса клиента
