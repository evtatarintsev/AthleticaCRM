## Why

Выданный абонемент сейчас — анемичная запись: доменный `Membership` не знает состояний, статус `ACTIVE | EXPIRED` вычисляется в маршруте по дате окончания в часовом поясе сервера, правило «заканчивается» живёт во фронте, а занятия с абонемента не списываются вовсе — `sessionsRemaining` не меняется после выдачи (issue #162). Без жизненного цикла и списаний абонемент не отвечает на главные вопросы администратора: можно ли по нему отметить клиента, с какого абонемента спишется занятие и кто из клиентов ходит без оплаты.

## What Changes

Изменение делится на четыре этапа, каждый поставляется отдельным PR.

**Этап 1. Жизненный цикл абонемента**
- Сохранённые состояния — явные типы в домене: `Неактивирован` → `Активный` → `Закрыт`; `Отозван` — из любого нефинального. `Закрыт` и `Отозван` финальные: переходов нет, но корректирующие записи (возврат занятия) допустимы.
- Свойства активного абонемента выводятся на дату в часовом поясе организации: положение даты относительно срока (не начался / в сроке / срок вышел), остаток занятий (есть / исчерпан / безлимит), «заканчивается» с причиной (по дате — ≤ 7 дней, по занятиям — ровно 1), «к закрытию» — только выводимое. Срок включает дату начала и дату окончания.
- Режим активации задаётся при выдаче: сразу; с указанной даты; при первом посещении с необязательной крайней датой. Дата активации никогда не переписывается и не бывает раньше даты выдачи (кроме явной даты в режиме «с даты»).
- Режим закрытия задаётся при выдаче: вручную; автоматически при списании последнего занятия; автоматически по истечении срока. Если абонемент «к закрытию», а режим его сам не закроет, выдавшему отправляется уведомление (один раз на эпизод).
- Фоновая обработка в часовом поясе организации: активация по дате, автозакрытие по сроку, уведомления «к закрытию».
- Действия «Закрыть» и «Отозвать» в карточке клиента.
- История абонемента: каждое действие и переход пишется транзакционно и видна в панели абонемента.
- **BREAKING (контракты)**: `MembershipSchema.status` (`ACTIVE | EXPIRED`) заменяется состоянием с выводимыми свойствами; `membershipEndingSoon` во фронте удаляется.

**Этап 2. Группы абонемента**
- При выдаче выбираются группы, в которых действует абонемент (хотя бы одна).

**Этап 3. Списания**
- Занятие списывается при проведении занятия за каждого участника с отметкой «пришёл».
- Подбор абонемента: активный, у которого дата занятия в сроке, группа занятия в списке групп и есть занятия (или безлимит); иначе неактивированный с режимом «при первом посещении» — он активируется датой занятия.
- Правка отметки в проведённом занятии возвращает занятие на абонемент или списывает его заново; возврат на закрытый абонемент допустим, состояние не меняется.
- Участник проведённого занятия без списания при отметке «пришёл» — неоплаченное занятие.
- Списания не теряются при временных сбоях: обработка доменных событий повторяется с нарастающей задержкой, неуспешные события не помечаются обработанными и перезапускаются администратором.
- В «Участниках» карточки занятия у каждого клиента показан абонемент, с которого будет (или было) списание, либо предупреждение об отсутствии абонемента.

**Этап 4. Погашение долга**
- Действие «Погасить долг» у активного абонемента: администратор выбирает любые неоплаченные занятия клиента в группах абонемента (в том числе до начала срока), каждое становится списанием с отметкой «погашение долга» в истории.
- После выдачи с немедленной активацией при наличии неоплаченных занятий панель выдачи предлагает погасить долг; можно выбрать часть или отказаться.
- Если абонемент активирован без участия администратора (по дате или первым посещением) и у клиента есть неоплаченные занятия в группах абонемента, создаётся задача «Проверить клиента» с привязкой к клиенту, без исполнителя и без автора-сотрудника («Система»). Задачи без исполнителя видны всем сотрудникам.

### Non-goals

Миграция существующих данных: проект не в продакшене, реальных абонементов и посещаемости нет. Миграции меняют только схему, существующие строки абонементов удаляются; корректность исторических данных (группы старых абонементов, долги по прошлой посещаемости, уведомления) не обеспечивается.


Заморозка и разморозка, лимиты заморозок; продление абонемента; деактивация (возврат в «Неактивирован»); оплата абонемента и связь с балансом клиента; списание за «не пришёл» с метками (прогул, штраф); ручной выбор абонемента для конкретного списания; ответственный сотрудник клиента; отдельные права на действия с абонементами.

## Capabilities

### New Capabilities
- `membership-lifecycle`: состояния выданного абонемента, режимы активации и закрытия, выводимые свойства на дату, фоновая обработка, история абонемента.
- `membership-debits`: группы абонемента, списание занятий при проведении, подбор абонемента, корректировки при правке отметок, неоплаченные занятия, погашение долга, задача после фоновой активации.
- `tasks`: видимость задач без исполнителя и задачи, созданные системой.
- `web-client/memberships`: абонементы в веб-клиенте — новые поля выдачи, состояние и признаки в карточке клиента, панель абонемента с историей и действиями, предложение погасить долг.

### Modified Capabilities
- `web-client/session-detail`: в списке участников показывается абонемент списания либо предупреждение об отсутствии абонемента.
- `web-client/tasks`: автор «Система» у системных задач.

## Impact

- **Сервер**: `domain/memberships` — типы состояний, переходы, история, списания; новые таблицы `membership_groups`, `membership_events`, `membership_debits` и колонки режимов в `memberships` (Liquibase); фоновый обработчик абонементов по аналогии с `DomainEventWorker`; обработчики `SessionCompleted` и `AttendanceChanged`; `read/` — проекции списка абонементов клиента, превью списаний для занятия, неоплаченных занятий; `routes/MembershipsRoutes.kt` — новые маршруты (`close`, `revoke`, `history`, `unpaid-sessions`, `repay-debt`); `domain/tasks`, `read/tasks` — задача без автора-сотрудника, видимость задач без исполнителя; `domain/events/DomainEventWorker` — повторы с задержкой, неуспешные события, admin-команда перезапуска.
- **Shared / контракты**: `IssueMembershipRequest` (режимы, группы), `MembershipSchema` (состояние вместо `status`), новые схемы; удаление `MembershipStatus`; перегенерация `web/src/api/generated/`.
- **Веб-клиент**: панель выдачи (`issue-subscription`), `ClientSubscriptionsSection`, `clientCardAlerts.ts`, карточка занятия; словари `ru.ts`/`en.ts`.
- **Связь с `issue-subscription-side-sheet`**: это изменение ещё не заархивировано, поэтому новые поля панели выдачи описаны в `web-client/memberships` как дополнение к шагу 2 «Условия», а не дельтой к его спеке.
