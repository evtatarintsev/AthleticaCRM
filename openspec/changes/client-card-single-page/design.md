## Context

После `client-overview-page` карточка клиента — шапка, полоса вкладок и шесть вкладок: «Обзор»
(четыре плитки, «Требует внимания», «Группы», «Контакты», «Переписка», «Последняя заметка»),
«Абонементы», «Занятия», «Анкета», «Задачи», «Заметки». Активная вкладка — в `?tab=`.

Каждый элемент «Обзора» уже ведёт к подробностям: плитка «Абонемент» и «+N» — к абонементам,
«Посещаемость» — к занятиям, «Последняя заметка» — к заметкам, строка просроченных задач — к
задачам. Вкладки дублируют «Обзор» в развёрнутом виде.

В приложении для подробностей уже принят другой приём — панель справа поверх страницы: баланс,
абонемент, выдача абонемента, чат, задача, разделы карточки.

## Goals / Non-Goals

**Goals:**
- Одна страница без вкладок: всё короткое — на ней, полное — в панели справа.
- Один приём для подробностей во всей карточке.
- Убрать с первого экрана то, с чем на карточке клиента не работают (плитка «Следующее занятие»).

**Non-Goals:**
- Изменение правил «Требует внимания», выбора основного абонемента, посещаемости, разделов
  карточки, серверных проекций и контрактов.
- Ссылки на конкретную панель (`?panel=`): панели в адрес не пишутся, как и прочие панели карточки.
- Карточка группы — там вкладки остаются.

## Decisions

**Панели вместо вкладок.**
| Было | Стало | Откуда открывается |
|---|---|---|
| вкладка «Абонементы» | панель «Абонементы» | «Все · N» на плитке «Абонемент» |
| вкладка «Занятия» | панель «Занятия» | плитка «Посещаемость» |
| вкладка «Задачи» | карточка «Задачи» + панель «Задачи» | «Все задачи», строка просроченных при нескольких |
| вкладка «Заметки» | карточка «Заметки» + панель «Заметки» | «Все заметки», «Добавить» |
| вкладка «Анкета» | карточка «Анкета» | — (поля короткие, видны целиком) |

Панели — существующие секции (`ClientSubscriptionsSection`, `ClientSessionsTab`,
`ClientActivitySections`, `ClientNotesSection`) в `EditSheet`. Панель абонемента или задачи,
открытая из панели-списка, открывается поверх неё; её закрытие возвращает к списку, а не к
странице — так пользователь не теряет место в списке.

**«Все · N» вместо «+N».** «+N» считал только неистёкшие и пропадал при одном абонементе, а
истёкшие тогда были недоступны без вкладки. «Все · N» показывается, когда у клиента больше одного
абонемента с учётом истёкших, N — их общее число.

**Плитка «Следующее занятие» убирается, ближайшее — у группы.** Ближайшее занятие считается по
каждой группе из уже загружаемого `schedule/list` тем же правилом (не отменено, ещё не началось,
14 дней). У клиента в двух группах так видно ближайшее по каждой. Нет ближайшего в 14 днях —
строка группы показывает «Ближайших занятий нет».

**Раскладка колонок.** Включаемых карточек нет — слева «Группы» и «Контакты», справа «Анкета».
Есть хотя бы одна из «Задачи», «Переписка», «Заметки» — слева «Группы», «Контакты», «Анкета»,
справа включённые в этом порядке. Так колонки близки по высоте в обоих наборах. Плитки: три в
ряд; < 1000 px — «Абонемент» на всю ширину, «Баланс» и «Посещаемость» парой; телефон — так же,
карточки одной колонкой.

**Старые адреса.** `?tab=` игнорируется без ошибки: ссылок с ним немного, и все ведут на ту же
карточку. `/visits` открывает карточку клиента.

## Risks / Trade-offs

- **Нет ссылки на «историю посещений клиента».** На практике ей не пользуются; при потребности
  — `?panel=` отдельным изменением.
- **Страница длиннее «Обзора»** на карточку «Анкета». Она короткая, и в полном наборе стоит в
  левой колонке, уравнивая её с правой.
- **Вложенные панели** (абонемент поверх списка) — глубина 2, как уже у баланса с корректировкой.
