# E2E-тесты

Смоук-набор Playwright на полном стенде. Проверяет те же образы и тот же
`nginx/prod.conf.template`, что уходят в прод. Устройство и мотивация описаны в openspec-изменении `e2e-tests`.

## Запуск

```bash
mise run e2e                          # собрать образы, поднять стенд, прогнать, удалить стенд
mise run e2e -- --keep                # стенд остаётся поднятым для повторных прогонов
mise run e2e -- --keep tests/clients.spec.ts -g "посещения"   # аргументы после --keep уходят в playwright test
```

`mise run e2e` вызывает `e2e/stand/run.sh`. Нужны Docker с Compose 2.24+ (оверлей использует `!reset`) и Node 24.
Зависимости `e2e/` скрипт ставит сам, если `node_modules` нет.

Если прогон упал:

- скрипт печатает последние строки логов `server`, `nginx`, `mailpit`;
- HTML-отчёт с трассами лежит в `e2e/playwright-report/index.html`. Открыть его: `cd e2e && npx playwright show-report`.

Стенд, оставленный через `--keep`, удаляется командой:

```bash
docker compose -p athletica-e2e -f docker-compose.prod.yaml -f e2e/stand/docker-compose.e2e.yaml \
  --env-file e2e/stand/e2e.env --profile test down -v
```

## Устройство стенда

Стенд — это `docker-compose.prod.yaml` с наложенным `stand/docker-compose.e2e.yaml`. Оверлей меняет только следующее:

| Что                             | Как                                                                                                                                                                                      |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server`, `clients`, `frontend` | образы `athletica-*:e2e` собираются из рабочей копии теми же Dockerfile                                                                                                                  |
| `nginx`                         | боевой шаблон без изменений; сертификат самоподписанный для `e2e.test` (`stand/certs.sh`); порты наружу не публикуются; хосты `app.e2e.test`, `minio.e2e.test` и другие — сетевые алиасы |
| почта                           | Mailpit (`mailpit:587`); тесты читают письма через его API                                                                                                                               |
| переменные                      | `stand/e2e.env`, только тестовые значения; ЮKassa в тестовом режиме, AI и прокси Telegram выключены                                                                                      |
| раннер                          | контейнер `mcr.microsoft.com/playwright` в той же сети, профиль `test`                                                                                                                   |

Раннер работает внутри сети compose, поэтому:

- не нужны `/etc/hosts`;
- порты хоста свободны, dev-стенд может работать параллельно;
- presigned-ссылки на `minio.e2e.test` открываются тем же браузером.

Версия образа раннера совпадает с точной версией `@playwright/test` в `package.json`. Меняются они вместе.

## Как писать сценарии

- **Организация на тест.** Фикстура `owner` (`support/fixtures.ts`) регистрирует новую организацию. Сессия владельца действует в `page`, а `owner.api` служит для подготовки данных. Базу никто не чистит, тесты идут параллельно.
- **Подготовка через API.** Её делает `support/data.ts`, а то, ради чего сценарий написан, проходит через интерфейс. Ответы API декодируются сгенерированными схемами `web/src/api/generated/contracts.ts` (`support/api.ts`): расхождение контракта со стендом роняет тест.
- **Селекторы.** Только `getByRole` и `getByLabel` с текстами из `web/src/i18n/ru.ts` (`support/i18n.ts`). Если у элемента нет доступной роли или подписи, сначала чинится доступность в `web/`. `data-testid` — крайний случай, и причина записывается здесь. Сейчас таких нет.
- **Ожидания.** Только web-first assertions, никаких `waitForTimeout`. Ретраев нет (`retries: 0`): нестабильный тест чинят или удаляют.
- **Письма.** `mailFor(request, адрес, регулярка)` (`support/mailbox.ts`) ждёт письмо опросом: рассылка уходит раз в несколько секунд.
- **Время.** Часы стенда не подменяются. Сценарии про «сегодня», продления и истечение остаются DB-тестам сервера. Если сценарию нужно прошедшее занятие, берётся вчерашняя дата (`yesterdayInOrg`).

## Отладка с UI-режимом Playwright

Ручной режим, `mise run e2e` его не использует.

1. Поднять стенд с `--keep`.
2. Временно опубликовать 443 у nginx, например `ports: ["443:443"]` в локальной копии оверлея.
3. Добавить в `/etc/hosts` строку `127.0.0.1 e2e.test app.e2e.test minio.e2e.test`.
4. Запустить `cd e2e && npx playwright test --ui`.

Письма в этом режиме недоступны: `mailpit` резолвится только внутри сети compose.
