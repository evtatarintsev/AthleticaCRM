## Context

Мотивация и состав — см. proposal.md, макет — `mockups/reports.html`.

Что уже есть и на что опираемся:

- **Навигация** — `web/src/app/sections.ts` (список разделов), `Navigation.tsx` скрывает «Финансы»
  без права через проп `canViewFinance`, `AppLayout.tsx` берёт права из `me.permissions`.
  Прямой заход без права — экран «нет доступа» (`FinancePage`: `hasPermission(session, …)`).
- **Права** — `shared/.../core/permissions/Permission.kt`; подписи и описания прав — словари
  `permission.<ID>.{label,name,description}`; владелец получает все права автоматически
  (`owner-all-permissions`), поэтому новое право не требует миграции.
- **Выгрузка** — `web/src/lib/download.ts` (`downloadBlob`); CSV сейчас собирает сервер
  (`FinanceRoutes.financeCsv`: UTF-8 с BOM, экранирование формул апострофом).
- **Данные извне** — zod-схемы; search-параметры маршрутов тоже декодируются zod.
- Графиков в `web/` нет. Макет рисует их CSS-ом: мини-столбцы на карточке, вертикальные столбцы
  (в том числе отрицательные и с подсветкой отдельных столбцов), столбцы «период / прошлый период»
  рядом, кольцевая диаграмма с легендой, горизонтальные полосы долей.

## Goals / Non-Goals

**Goals:**
- Каркас, в который девять изменений отчётов встраиваются параллельно: каждое добавляет запись в
  реестр и свои файлы, общие файлы почти не трогает.
- Одна библиотека графиков за одной обёрткой: отчёты не импортируют библиотеку напрямую.
- Правило периода и прошлого периода — в одном месте, без копий в вебе и на сервере.
- Остальные разделы `web/` не тяжелеют от графиков.

**Non-Goals:**
- Показатели отчётов и их маршруты — в изменениях отчётов (здесь — только маршруты таблицы
  показателей, пустой до первого отчёта).
- Настройка состава и порядка карточек, избранные отчёты, рассылка отчётов.
- Выгрузка экрана отчёта (графиков, списков) — выгружается только таблица показателей.
- Печать и PDF.

## Decisions

### 1. Графики — Recharts 3

Recharts (3.x, React 16.8–19, SVG) покрывает всё из макета и линии, которые понадобятся позже:
`BarChart` с отрицательными значениями и `Cell` для цвета отдельного столбца, сгруппированные
столбцы, `PieChart` с `innerRadius` для кольца, `ResponsiveContainer`. Слой доступности
(`accessibilityLayer`) включён по умолчанию: фокус и стрелки по точкам, подсказка читается.
Типы в пакете; подход совпадает со стеком `web/` (Radix + Tailwind + cva — те же графики, что у
shadcn/ui).

Отклонено:
- **Свои SVG/CSS-компоненты.** Для макета хватило бы, но оси, подписи, подсказки, адаптивная
  ширина и доступность с клавиатуры пришлось бы писать и поддерживать на девять отчётов.
- **visx** — низкоуровневые примитивы d3: по объёму кода то же, что свои компоненты.
- **Chart.js, ECharts** — canvas: текста в DOM нет, хуже для доступности и для тестов на
  Testing Library; ECharts к тому же самый тяжёлый и императивный.
- **Nivo** — тяжелее Recharts и тянет собственную систему тем поверх Tailwind.

Цена — размер: Recharts тянет `@reduxjs/toolkit`, `immer`, `victory-vendor` (d3). Поэтому раздел
«Отчёты» грузится отдельным чанком (§6), остальные разделы его не скачивают.

Обёртка — `web/src/reports/charts/`:

| Компонент | Где в макете | Основа |
|---|---|---|
| `Sparkline` | мини-график карточки | `BarChart` без осей и подсказок, фиксированный размер |
| `BarsChart` | «По дням», график на плашке экрана | `BarChart`, цвет столбца — функция от точки, подсказка — готовая строка |
| `CompareBars` | «период / прошлый период» | `BarChart` с двумя `Bar` и легендой |
| `DonutChart` | «В какие кассы пришли», «Почему не пришли» | `PieChart` + легенда списком; число в центре |
| `ShareBars` | горизонтальные полосы долей | **без библиотеки**: `div` с шириной в процентах |

Отчёты передают числа и готовые подписи (деньги — `format.money` из `useI18n`, остальное — по
словарям); цвета и оформление подсказки — внутри обёртки. Цвета групп («Деньги», «Клиенты», «Команда»,
«Сравнения») — CSS-переменные темы Tailwind, обёртка берёт их по имени группы.
У каждого графика есть `aria-label` с текстовым пересказом (как в макете), мини-график
на карточке — `aria-hidden`: цифра и изменение рядом уже есть текстом.

Тесты: в jsdom нет раскладки, `ResponsiveContainer` рисует график нулевого размера. Обёртка
принимает необязательные `width`/`height`; в тестах их задают, а проверяют `aria-label` и подписи,
а не SVG-пути.

Риск — строгость `web/`: `type-coverage --strict` 100% и `strictTypeChecked` на типах
форматтеров Recharts (`ValueType`, `NameType`). Проверено на `BarsChart`: собственные типы
Recharts проходят без `as` (подсказка ищет готовую строку по ключу столбца, цвет столбца — через
`shape`, а не устаревший `Cell`). Не проходит `index.d.mts` зависимости `@reduxjs/toolkit`
(`exactOptionalPropertyTypes` при `skipLibCheck: false`). Отключать `skipLibCheck` целиком не
стали: типы только этого пакета подменены для `tsc` через `paths` на
`web/src/vendor-types/reduxjs-toolkit.d.ts` — то немногое, что видно в объявлениях Recharts;
исключение записано в `web/README.md`.

### 2. Выгрузка — общая, на сервере

Выгрузки уже есть у клиентов и в финансах и будут у других списков, поэтому файл собирает сервер
одним общим механизмом, а таблица показателей отчётов — серверная проекция (§4), которую
выгрузка переиспользует.

Сейчас каждая выгрузка пишет CSV по-своему: `FinanceRoutes.financeCsv` — через commons-csv с BOM и
экранированием формул, `ClientsRoutes.generateCsvContent` — склейкой через `,` без кавычек и
экранирования, а на `format=xlsx` отдаёт те же CSV-байты с типом xlsx.

Общий механизм — `routes/export/TableExport.kt`:

```kotlin
/** Формат файла выгрузки. */
enum class ExportFormat { CSV, XLSX }

/** Ячейка выгрузки: тип определяет запись в CSV и формат ячейки в Excel. */
sealed interface ExportCell {
    data class Text(val value: String) : ExportCell
    data class Number(val value: Long) : ExportCell
    data class Percent(val value: Double) : ExportCell
    data class Amount(val value: Money) : ExportCell
    data class Day(val value: LocalDate) : ExportCell
    data object Empty : ExportCell
}

/** Таблица выгрузки: заголовки [headers] и строки [rows] одинаковой длины. */
data class ExportTable(val headers: List<String>, val rows: List<List<ExportCell>>)

/** Выставляет заголовки файла [filename] в формате [format] и возвращает его содержимое. */
fun RoutingCall.exportFile(filename: String, format: ExportFormat, table: ExportTable): ByteArray
```

- **CSV** — commons-csv, UTF-8 с BOM, правила `financeCsv`: текстовые ячейки, начинающиеся с
  `= + - @` или с табуляции/перевода строки, — с апострофом; числа, проценты и суммы не
  экранируются (иначе `-80` станет текстом). Сумма пишется числом без валюты.
- **XLSX** — `org.dhatim:fastexcel` (writer уже в `libs.versions.toml` для тестов; переносится в
  `implementation`): потоковая запись, без Apache POI. Числа и суммы — числовые ячейки с форматом
  (`# ##0.00` + символ валюты организации), проценты — `0.0%`, даты — формат даты; заголовок жирный,
  ширина колонок по содержимому. Строки-формулы не пишутся вовсе — только значения.
- Формат — `ExportFormat` из `shared`. У выгрузок клиентов и финансов — query-параметр `format`
  (`?format=xlsx`, по умолчанию CSV), у таблицы отчётов — поле `format` в теле запроса: веб-клиент
  передаёт параметры POST только телом. Имя файла — латиницей (`reports-2026-11-01-2026-11-27.xlsx`).

В этом изменении на механизм переводятся существующие выгрузки финансов (журнал, ДДС) и клиентов
— это и исправление выгрузки клиентов в Excel. Веб не получает новых зависимостей: кнопки
«Excel» / «CSV» вызывают маршрут и отдают ответ в `downloadBlob`.

Отклонено: сборка файла в браузере (`write-excel-file`, SheetJS, ExcelJS) — у каждого нового
списка был бы второй механизм рядом с серверным; Apache POI — тяжелее fastexcel и не нужен для
записи значений.

### 3. Период, прошлый период и филиал

Правило прошлого периода живёт в `shared` и считается на сервере; веб передаёт выбор
пользователя и показывает даты из ответа. Так правило одно и для веба, и для будущих
KMP-клиентов, а «сегодня» берётся в routes (как требует CLAUDE.md для проекций) — сценарии по
дате тестируются.

Выбор пользователя:

| Пункт | Период | Прошлый период |
|---|---|---|
| Этот месяц | 1-е число … сегодня | тот же отрезок прошлого месяца (конец — не позже последнего дня месяца) |
| Прошлый месяц | весь прошлый месяц | весь позапрошлый месяц |
| 30 дней | сегодня и 29 дней до | 30 дней вплотную перед ним |
| Квартал | начало квартала … сегодня | тот же отрезок прошлого квартала |
| Свой период | `from` … `to` | на выбор: «те же дни перед ним» (та же длина вплотную) или «тот же отрезок месяцем раньше» (обе даты на месяц назад, с обрезкой до конца месяца) |

«Сегодня» — в часовом поясе организации. Свой период ограничен 366 днями и не заходит в будущее.

Схема запроса (`shared/.../api/schemas/reports/ReportFilter`: пункт или свой период с режимом
сравнения, `branchId?`) и расчёт дат с тестами появляются в этом изменении: их уже принимает
маршрут таблицы показателей (§4). Расчёт — `ReportPeriods` в `shared` (`period` и `basePeriod`
по фильтру и `today`); проверка своего периода (`from` ≤ `to`, не больше 366 дней, не в будущем) —
smart constructor по правилам CLAUDE.md. Ответ таблицы и каждого отчёта содержит `period` и
`basePeriod` датами — по ним веб пишет «к 1–27 октября».

Состояние фильтров — search-параметры `/reports` и `/reports/$reportId`
(`period=month|last-month|30d|quarter|custom`, `from`, `to`, `compare=days-before|month-before`,
`branch`, `view=cards|table`), декодируются zod-схемой с запасным значением «Этот месяц».
Переход с карточки на отчёт и «← Все отчёты» сохраняют параметры: ссылкой можно поделиться.

Филиал: список — доступные сотруднику филиалы (`ctx.employee.availableBranches`); «Все филиалы»
означает все доступные. Сервер всё равно ограничивает запрос доступными филиалами.

### 4. Реестр отчётов

`web/src/reports/registry.ts` — девять записей в порядке макета:

```ts
/** Описание отчёта для страницы раздела. */
interface ReportDefinition {
  readonly id: ReportId; // "revenue" | "pnl" | "debts" | …
  readonly group: ReportGroup; // "money" | "clients" | "team" | "compare"
  readonly icon: LucideIcon;
  /** Права сверх CAN_VIEW_REPORTS. */
  readonly requires: readonly Permission[];
  /** Готовая часть отчёта; `undefined` — заглушка «скоро». */
  readonly impl?: ReportImpl;
}

interface ReportImpl {
  /** Карточка виджета: загружает свою сводку и рисует `ReportCard`. */
  readonly Card: ComponentType<{ filter: ReportFilter }>;
  /** Экран отчёта по шаблону `ReportScreen`. */
  readonly Screen: ComponentType<{ filter: ReportFilter }>;
}
```

Название и вопрос — ключи словаря `reports.<id>.name` / `reports.<id>.question`, иконка и группа —
из макета. Изменение отчёта заполняет `impl` своей записи; общие файлы, которые оно ещё трогает, —
словари.

Каждая карточка грузит свою сводку отдельным запросом TanStack Query: отчёты не ждут друг друга,
ошибка одного не ломает страницу (карточка показывает «не удалось загрузить» и «повторить»).

Таблица показателей — серверная, один запрос: её же отдаёт выгрузка (§2), поэтому экран и файл
совпадают по определению.

- `POST /api/reports/table` (`ReportsTableRequest` = `ReportFilter`) →
  `ReportsTableResponse(period, basePeriod, rows)`, строка —
  `{ reportId, label, value, base, better }`, значение — `ReportValue` (`Amount` / `Count` /
  `Percent`) из `shared`; изменение считает веб для показа и сервер для файла по общему правилу.
- `POST /api/reports/table/export` (`ReportsTableRequest` + `format`) → файл через
  `exportFile`, колонки «Показатель», «Период», «Прошлый период», «Изменение».
- Строки поставляют источники `ReportTableSource` (`read/reports/`):
  `requires: Set<Permission>` и `rows(filter, periods)`; список источников — в `ReadViews`.
  Маршрут требует `CAN_VIEW_REPORTS` и берёт только источники, на которые хватает прав, — так в
  файл не попадают денежные строки без права на деньги. Подписи строк — серверным `i18n/` по
  языку сотрудника.
- В этом изменении источников нет: маршруты отвечают пустой таблицей. Изменение отчёта добавляет
  свой источник поверх своей проекции-сводки.

Видимость: `CAN_VIEW_REPORTS` и все права из `requires`. «Долги клиентов» —
`CAN_VIEW_CLIENT_BALANCE`; «Выручка», «Доходы и расходы», «Филиалы» — `CAN_VIEW_FINANCE`.
Группа без видимых карточек не показывается. Сервер проверяет те же права в маршруте каждого
отчёта — это требование спецификации `reports`, реализуется в изменениях отчётов.

### 5. Шаблоны

- `ReportCard`: иконка в цвете группы, название, вопрос, главная цифра, плашка изменения,
  `Sparkline`, необязательное предупреждение (`warning` / `danger`). Цвет плашки задаёт сам отчёт
  через `better: "up" | "down"` (для долгов рост — к худшему); изменение без прошлого периода
  (нет данных) не показывается. Вся карточка — ссылка на экран отчёта.
- `ReportStubCard`: название, вопрос, «скоро»; не ссылка, без цифр.
- `ReportScreen`: «← Все отчёты», заголовок и фильтры; цветная плашка с главной цифрой,
  изменением и `BarsChart` за последние периоды; три `ReportTile`; слоты для разбивок
  (`ReportSection` — карточка с заголовком), списка людей (`ReportPeople`: имя, подпись, ссылка
  на карточку клиента) и строки «Как считается».
- `ReportsTable`: строки из `/api/reports/table` (§4), колонки «Показатель», «Период»,
  «Прошлый период», «Изменение»; кнопки «Excel» и «CSV» вызывают `/api/reports/table/export`
  с тем же фильтром. Пока строк нет — пустое состояние, кнопки выгрузки недоступны.

### 6. Маршруты и загрузка

- `/reports` — страница раздела; `/reports/$reportId` — экран отчёта: `reportId` проверяется по
  реестру, неизвестный, заглушка или нет прав → «не найдено» / «нет доступа».
  Один маршрут на все отчёты вместо девяти: изменения отчётов не правят `router.tsx`.
- Компоненты раздела подключаются через `lazyRouteComponent`, поэтому Recharts попадает в чанк
  раздела. Проверка — `vite build`: в основном чанке нет `recharts`.
- Пункт «Отчёты» (иконка `ChartColumnIcon`) — между «Финансами» и «Настройками», как в макете;
  виден с `CAN_VIEW_REPORTS` (проп `canViewReports` по образцу `canViewFinance`).

### 7. Право «Видеть отчёты»

`CAN_VIEW_REPORTS` в `Permission.kt` с KDoc, подписи в словарях, место в окне роли рядом с
`CAN_VIEW_FINANCE`. Сотрудникам и ролям не выдаётся автоматически; владельцу — как и все права.
В демо-данных — роли управляющего. Контракты перегенерировать (`npm run contracts`).

## Risks / Trade-offs

- **Типы Recharts и строгость `web/`** → первая задача — проверка на одном графике (§1).
- **Размер Recharts** → отдельный чанк раздела (§6), проверка по выводу `vite build`.
- **Девять параллельных изменений** правят `registry.ts`, список источников в `ReadViews` и
  словари → у каждого отчёта своя строка в реестре и в списке, свой префикс ключей
  `reports.<id>.*`; конфликты — построчные.
- **Перевод выгрузок клиентов и финансов на общий механизм** меняет их файлы: у клиентов
  появляются кавычки, BOM и настоящий xlsx; у финансов суммы становятся числами без символа
  валюты → описать в PR; e2e на выгрузку клиентов, если есть, прогнать.
- **Карточек девять — запросов девять** на открытие раздела → допустимо: запросы параллельные и
  лёгкие (одна сводка); если станет медленно, сводки объединяются в один маршрут без изменения
  карточек (меняется только `useQuery` в `impl`).

## Migration Plan

Миграций БД нет. Раздел выкатывается с заглушками: пункт меню видят только сотрудники с новым
правом (по умолчанию — владелец). Откат — удаление пункта и маршрутов; право в enum безвредно.
