# Proposal

## Why

В карточке занятия (`/sessions/$sessionId`) «← Назад» всегда ведёт в `/schedule`, хотя журнал
открывают ещё с главной, из карточек группы и клиента и из журнала аудита. Пользователь,
пришедший не из расписания, попадает не туда, откуда открыл журнал (issue #247).

## What Changes

- «Назад» в карточке занятия возвращает на предыдущую страницу приложения, если она есть
  в истории вкладки.
- Если предыдущей страницы приложения нет (прямая ссылка, новая вкладка, вход через логин),
  «Назад» ведёт в `/schedule`, как сейчас: на неделю занятия, а пока данные занятия
  неизвестны — без search-параметров.
- Адрес ссылки остаётся `/schedule`, поэтому «открыть в новой вкладке» продолжает работать.
- Отменяет для карточки занятия правило «независимо от истории браузера» из изменения
  `detail-page-back-links`. Карточки группы и клиента не меняются.

## Capabilities

### New Capabilities

_Нет._

### Modified Capabilities

- `web-client/session-detail`: требование «Переход на карточку занятия из расписания и с главной»
  — «Назад» возвращает на предыдущую страницу приложения, а в `/schedule` ведёт только
  при её отсутствии.

## Impact

- `web/src/ui/BackLink.tsx` — необязательный обработчик возврата.
- `web/src/sessions/SessionDetailPage.tsx` — передаёт обработчик в `BackLink` во всех ветках.
- `web/src/app/router.tsx` — маршрут занятия собирает обработчик из истории роутера.
- `web/src/sessions/SessionDetailPage.test.tsx` — тесты возврата.
- API и сервер не затрагиваются.
