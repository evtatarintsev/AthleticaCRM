## Why

Организациям нужно отправлять одноразовые коды в Telegram по номеру телефона: для входа в
приложения клиента и тренера, а позже для двухфакторной аутентификации. Telegram Gateway API
делает это без бота и без того, чтобы человек сначала кому-то писал, и стоит дешевле SMS. Платит
сама организация, со своего аккаунта Gateway, поэтому подключать его нужно в настройках
организации, а не в конфигурации сервера.

## What Changes

- Новый раздел настроек организации «Telegram Gateway». Администратор вводит токен своего
  аккаунта Gateway. До сохранения токен проверяется у Telegram, а потом отдаётся только маской.
  Интеграцию можно выключить и снова включить, токен — заменить.
- Сервер умеет отправить код в Telegram от имени организации. Код и срок его жизни задаёт
  вызывающий. До отправки сервер проверяет, можно ли доставить сообщение на номер, и за пару
  «проверка + отправка» платит один раз. Вызывающий получает один из исходов: отправлено,
  на номер доставить нельзя, интеграция не настроена или выключена, ошибка.
- В настройках виден остаток баланса Gateway по последнему платному ответу.
- Из настроек можно отправить тестовый код на указанный номер и убедиться, что интеграция работает.
- **Не входит**:
  - кто, когда и зачем отправляет коды (вход в приложения, 2FA);
  - хранение и проверка кодов, лимиты;
  - переход на SMS;
  - отчёты о доставке через `callback_url`;
  - `checkVerificationStatus` и `revokeVerificationMessage`;
  - отправка от проверенного канала организации (`sender_username`).

### New Capabilities

## Impact

- **server**:
  - `infra/telegram/gateway/` — HTTP-клиент Gateway API с теми же прокси `telegram.proxies`,
    что у Bot API;
  - домен интеграции организации: хранение настроек и сервис отправки кода;
  - маршруты настроек и тестовой отправки;
  - миграция БД с таблицей настроек Gateway организации.
- **shared**: схемы запросов и ответов настроек Gateway.
- **web**: страница настроек «Telegram Gateway», перегенерация `web/src/api/generated/`.
- **Конфигурация**: новых переменных окружения нет, токен хранится в БД организации.
- **Внешние зависимости**: Telegram Gateway API. Аккаунт и баланс у каждой организации свои.
- **Связанные изменения**: `client-mobile-app` пока ссылается на это изменение как на
  реализацию `VerificationCodeSender`. Связь с сервисом отправки описывается там, когда будет
  решено, кто отправляет коды.
