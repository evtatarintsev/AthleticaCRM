## Context

Карточка занятия `/sessions/$sessionId` (`web/src/sessions/SessionDetailPage.tsx`) работает на
моках (`sessionDetailMock.ts`): участники с выдуманными `ClientId`, отметки посещаемости
(`AttendanceStatus`: `PRESENT` / `ABSENT` / `SICK` / `LATE`) живут в локальном `useState` страницы.
На карточке клиента кнопка «История посещений» ведёт на `/clients/$clientId/visits`, где сейчас
`ClientComingSoonPage`. На сервере посещаемости нет вообще: ни таблицы, ни схем, ни проекций.

## Goals / Non-Goals

**Goals:**
- Дать переход из участника занятия в его историю посещений без потери контекста занятия.
- Заменить заглушку журнала посещений клиента на работающий (на моках) экран.
- Держать форму мок-записи близкой к будущей схеме ответа API, чтобы переход на реальные данные
  был заменой одного файла на `useQuery`.

**Non-Goals:**
- Хранение посещаемости на сервере, read-проекция `ClientAttendanceView`, списание занятий с
  абонемента — отдельный change после согласования UX.
- Права доступа к журналу посещений.
- Колонка «Тип занятий» (групповое / индивидуальное / пробное) — в продукте сейчас только групповые
  занятия.
- Согласованность мок-истории с реальными клиентами: на `/clients/<реальный id>/visits` будет
  показана мок-история, порождённая по id.

## Decisions

**Панель (`Sheet`), а не переход на страницу клиента.** Основной сценарий — отметить всю группу и
по ходу заглянуть в 2–3 учеников. Переход на другую страницу ломает этот поток и требует возврата.
`Sheet` уже есть в `web/src/components/ui/sheet.tsx` и используется в `ClientsFiltersSheet`.
Полный переход остаётся доступен ссылкой «Открыть карточку» в шапке панели.

**Открытый ученик — в search-параметре `client`**, а не в `useState`. Маршрут `/sessions/$sessionId`
получает `validateSearch` с zod-схемой `{ client?: ClientId }`; невалидное значение трактуется как
«панель закрыта». Открытие панели — `navigate({ search: { client } })`, закрытие — удаление
параметра. Так «Назад» в браузере закрывает панель, а состояние переживает перезагрузку.

**Один компонент истории на два экрана.** `web/src/clients/ClientAttendanceHistory.tsx` принимает
`entries` и опциональный `highlightSessionId`, рисует сводку и таблицу. `ClientAttendanceSheet`
(панель) и `ClientVisitsPage` (страница) отличаются только обёрткой и фильтром периода на странице.

**Мок-слой `web/src/sessions/attendanceMock.ts`:**
- `AttendanceEntry` — `{ sessionId, date, startTime, groupName, coachName, membershipName | null,
  status, comment }`; повторяет вероятную будущую `ClientAttendanceItemSchema`.
- `mockClientAttendance(clientId)` детерминированно (хэш id, как в `mockSessionDetail`) порождает
  10–15 записей со всеми статусами, часть — без абонемента.
- `withCurrentSession(entries, detail, clientId)` — чистая функция: добавляет или заменяет запись
  текущего занятия статусом из state карточки. Поэтому переключение статуса на странице сразу видно
  в открытой панели без общего глобального стора.
- `attendanceSummary(entries)` — сводка «посетил / пропустил».

**Правило сводки:** «Был» и «Опоздал» считаются посещением, «Не был» и «Болел» — пропуском (как
«Посетил / Пропустил» в привычных CRM). Правило изолировано в `attendanceSummary` и может быть
пересмотрено при проектировании API (вопрос списания «Болел» с абонемента — там же).

**Иконки статусов:** ✓ (зелёная) — был, — (красная) — не был, отдельные иконки lucide для «болел» и
«опоздал»; рядом всегда текстовая подпись для доступности (`aria-label` / `sr-only`).

**Фильтр периода на странице журнала** — search-параметры `from` / `to` (`LocalDate`), декодируются
zod; по умолчанию — без ограничения. Фильтрация — чистая функция над записями мока.

## Risks / Trade-offs

- **[Риск]** Мок-история на реальных клиентах может быть принята за настоящие данные →
  **Митигация**: экран не выкатывается пользователям до подключения API, это этап согласования UX
  (как и карточка занятия).
- **[Риск]** Форма `AttendanceEntry` разойдётся с реальной схемой → **Митигация**: тип и вся логика
  изолированы в `attendanceMock.ts`, компоненты принимают готовые записи.
- **[Trade-off]** Состояние отметок не разделяется между вкладками и страницей журнала: отметка на
  карточке занятия не видна на `/clients/$clientId/visits` после перехода. Принято — общий стор ради
  мока не оправдан.
