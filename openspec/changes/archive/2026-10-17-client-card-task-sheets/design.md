## Context

Блок «Задачи» карточки клиента — `ClientTasksSection` в `web/src/clients/ClientActivitySections.tsx`.
Кнопка «+» в нём — `<Link to="/tasks" search={{ create: true }}>`, строка задачи —
`<Link to="/tasks" search={{ task: id }}>`. Задачи блока загружает `clientTasksQuery`
(`tasks/list` с `clientId`). Этот же запрос `ClientDetailPage` использует для предупреждения о
просроченных задачах в шапке.

Обе панели задач уже не зависят от страницы `/tasks`:

- `TaskCreateSheet({ api, open, onOpenChange })`: форма монтируется заново при каждом открытии и
  начинается с `EMPTY_TASK_FORM`;
- `TaskSheet({ api, taskId, onClose })`: открыта, пока `taskId !== null`. Сама грузит
  `tasks/detail`, внутри открывает `TaskEditSheet`.

`TasksPage` только хранит открытую панель в search-параметрах и передаёт её в эти компоненты.

Все три панели после изменений сбрасывают кэш по префиксу `["api", branchId, "tasks/list"]`. Ключ
`clientTasksQuery` — `["api", branchId, "tasks/list", { clientId, limit }]`, то есть он под этот
префикс попадает.

Панели карточки клиента (`ClientBalanceSheet`, `MembershipSheet`, `IssueSubscriptionSheet`) живут в
`ClientDetailPage` на локальном `useState`, без записи в адрес.

## Goals / Non-Goals

**Goals:**
- Переиспользовать существующие `TaskCreateSheet` и `TaskSheet` без копий и обёрток.
- Заблокированный клиент — свойство формы создания, а не карточки клиента: позже его можно
  переиспользовать в другом контексте (например, в группе или занятии).

**Non-Goals:**
- Запись открытой панели задачи в адрес карточки клиента.
- Блокировка клиента в форме редактирования задачи, открытой из карточки клиента.
- Изменения в разделе `/tasks`, на бэкенде и в контрактах API.

## Decisions

### Фиксированный клиент — необязательный проп `TaskCreateSheet`

`TaskCreateSheet` получает `client?: PickedClient`. Если он передан:

- начальные значения формы — `{ ...EMPTY_TASK_FORM, client }`. Клиент входит в `defaultValues`,
  поэтому TanStack Form не считает форму изменённой, и закрытие без ввода проходит без
  подтверждения (это есть в spec);
- `ClientPickerSheet` среди вложенных панелей не монтируется;
- в `TaskFields` поле клиента рисуется только для чтения.

Сохраняется форма тем же путём: в `tasks/create` уходит `values.client.id`.

Рассматривали вариант не показывать поле клиента вовсе. Отклонён: пользователь хочет видеть, к кому
привязывается задача.

Рассматривали `PickerField` с `disabled`. Отклонён: приглушённая кнопка со стрелкой читается как
«временно недоступно», а не как «задано контекстом».

### Режим поля клиента в `TaskFields` — через `onPickClient: (() => void) | null`

`null` означает, что клиента выбрать нельзя. Тогда `TaskFields` показывает подпись и имя клиента
статичным блоком тех же размеров, что `PickerField`, но без кнопки, стрелки и крестика. Отдельный
булев флаг рядом с колбэком допускал бы противоречивое состояние «заблокировано, но колбэк есть».

`TaskEditSheet` по-прежнему передаёт колбэк, и его поведение не меняется.

### Панели принадлежат `ClientDetailPage`

`ClientDetailPage` хранит `taskCreateOpen: boolean` и `openTaskId: TaskId | null` и рисует
`<TaskCreateSheet client={{ id, name }}>` и `<TaskSheet taskId={openTaskId}>` рядом с остальными
панелями карточки. `ClientTasksSection` вместо ссылок получает колбэки `onCreate()` и
`onOpen(taskId)`. Строка задачи становится кнопкой с тем же видом, что ссылка сейчас.

Имя клиента берётся из уже загруженного `clients/detail`. Панель создания рисуется только при
загруженных данных клиента, как `ClientBalanceSheet`.

Рассматривали вариант, в котором панели живут внутри `ClientTasksSection`. Отклонён: блок карточки
настраивается (`clientCardBlocks`) и может быть скрыт, а все панели карточки сейчас принадлежат
странице.

### Обновление блока — без нового кода

После создания и изменений `TaskCreateSheet`, `TaskSheet` и `TaskEditSheet` уже сбрасывают кэш
`tasks/list`. Этого хватает, чтобы перезапросились блок «Задачи» и предупреждение о просроченных
задачах. Отдельный `onChanged` не нужен.

## Risks / Trade-offs

- [В `TaskSheet` клиент — ссылка на `/clients/$clientId`, и из карточки клиента она ведёт на ту же
  страницу] → Переход на тот же адрес ничего не делает, панель остаётся открытой. Оставляем как есть,
  чтобы не добавлять в `TaskSheet` проп ради одного места.
- [Открытая с карточки задача не переживает перезагрузку страницы] → Так же ведут себя остальные
  панели карточки. Если понадобится ссылка, можно добавить search-параметр к маршруту клиента, не
  меняя компонентов панелей.
- [После отвязки клиента в редактировании задача пропадает из блока, а её карточка остаётся
  открытой] → Ожидаемо и описано в spec. `TaskSheet` берёт данные из `tasks/detail`, а не из
  списка блока.
