## Context

- `POST /sessions/create` → `createSession` → `Sessions.new` уже создаёт занятие без слота (`origin_slot_id IS NULL`), то есть «вне расписания»; сверка такие занятия не трогает.
- `createSession` сам подставляет тренеров группы (`employees.byIds(group.employeeIds)`); `Sessions.new` проверяет, что группа из организации и тренеры имеют доступ к филиалу группы, а зал не проверяет вовсе. `Session.reschedule` пишет `hall_id` без проверки.
- `halls` содержит `org_id` и `branch_id`, так что проверка — один SQL.
- Веб: `ScheduleWeekGrid` уже рисует шапку из 7 дней и строки только для занятых часов; при пустой неделе `SchedulePage` вместо сетки показывает сообщение. `GroupListItem` уже содержит `employees`, `GET /halls/list` отдаёт залы — новых эндпоинтов для панели не нужно.

## Goals / Non-Goals

**Goals:** UI создания занятия вне расписания на странице расписания; явный состав тренеров в запросе; проверка зала при создании и переносе.

**Non-Goals:**
- проверка пересечений по залу и тренеру;
- новое право на управление занятиями (сейчас для занятий прав нет — сохраняем);
- редактирование/отмена занятия из сетки;
- подстановка часа или длительности из расписания группы.

## Decisions

**Действие «[+]» в шапке дня, а не в ячейке.** Строки есть только для занятых часов, поэтому кнопка в ячейке намекает на час, которого может не быть (занятия в 10 и 20, добавить нужно в 15). Шапка видна всегда, одинакова для пустой и заполненной недели. Отвергнуты: кнопки в каждой ячейке (шум, ложная привязка к часу); одна кнопка в шапке страницы (теряется предзаполнение даты). Иконка — `ghost`, приглушённая, видна постоянно (наведения на тачскрине нет), `aria-label` с датой дня.

**Пустая неделя — сетка, а не сообщение.** Иначе исчезает шапка с «[+]». `ScheduleWeekGrid` при пустом наборе рисует одну строку на всю ширину с текстом «Занятий нет». Тот же путь — для «под фильтр ничего не подходит» и группы другого филиала.

**`employeeIds` обязательное, допускается `[]`.** Сервер не додумывает состав: что пользователь видит отмеченным в панели, то и сохраняется. Подстановку тренеров группы делает фронт при выборе группы (данные уже в `GroupListItem.employees`). Отвергнуто «`null` → тренеры группы»: два смысла у одного поля и неочевидное поведение для `[]`.

**Флаг `is_employee_assignment_overridden` при создании не ставится.** Флаг означает отклонение от состава, предписанного слотом, и защищает занятие от сверки; у ручного занятия слота нет, сверка его не трогает. `Sessions.new` уже вставляет с `DEFAULT FALSE` — менять ничего не нужно, только зафиксировать тестом. Последующая смена тренеров через `set-employees` выставляет флаг как обычно — не трогаем.

**Проверка зала — в домене, рядом с проверкой группы.** В `DbSessions.new` после получения `branch_id` группы: `SELECT 1 FROM halls WHERE id = :hallId AND org_id = :orgId AND branch_id = :branchId`, иначе `raise(CommonDomainError("HALL_NOT_FOUND", …))`. В `DbSession.reschedule` — та же проверка по `branch_id` группы занятия. Ошибка «не найдено», а не «запрещено»: чужой зал не должен раскрывать своё существование. Сообщение — через `Messages` с локализацией, как `GroupNotFound`.

**Идемпотентность — клиентский `id`.** `id` занятия генерируется при открытии панели и сохраняется до её закрытия; кнопка блокируется на время запроса. Повтор с тем же `id` упирается в PK и возвращает `SESSION_ALREADY_EXISTS` — дубля не будет.

**Панель — `EditSheet`.** Как остальные боковые панели (`IssueSubscriptionSheet` и др.). Группы — из `/groups/list` текущего филиала, залы — `/halls/list`, тренеры — существующий список сотрудников с `MultiSelectPicker`. После успеха — инвалидация запроса расписания.

## Risks / Trade-offs

- [BREAKING `CreateSessionRequest`] → внешних потребителей нет, веб его ещё не вызывает; контракты перегенерируются в том же изменении.
- [Повтор после сетевой ошибки покажет `SESSION_ALREADY_EXISTS`, хотя занятие создано] → редкий случай; сетка после закрытия панели покажет занятие. Не усложняем.
- [Семь иконок в шапке добавляют шума] → приглушённый `ghost`-стиль; при необходимости можно перейти на показ по наведению на колонку для десктопа без изменения спеки.
- [Можно создать занятие задним числом] → осознанно разрешено (досоздать забытое занятие и отметить посещение); такое занятие попадает под контроль незакрытых журналов.
