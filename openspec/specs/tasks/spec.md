# tasks Specification

## Purpose

Серверные правила задач, которые нужны системным задачам: видимость задач без исполнителя и задачи, созданные системой, а не сотрудником.

## Requirements

### Requirement: Задача без исполнителя видна всем сотрудникам

Список задач сотрудника без права просмотра всех задач SHALL включать задачи, где он исполнитель или автор, и все задачи организации без исполнителя. Фильтр «только мои» SHALL оставлять только задачи, где сотрудник исполнитель или автор. Карточка задачи без исполнителя SHALL открываться любому сотруднику организации.

#### Scenario: Системная задача видна сотруднику без права

- **WHEN** система создала задачу без исполнителя, а список запрашивает сотрудник без права просмотра всех задач
- **THEN** задача есть в списке

#### Scenario: Чужая назначенная задача не видна

- **WHEN** задача назначена другому сотруднику и создана не запрашивающим
- **THEN** у сотрудника без права просмотра всех задач её нет в списке

#### Scenario: «Только мои» без неназначенных

- **WHEN** сотрудник включает фильтр «только мои»
- **THEN** задачи без исполнителя, созданные не им, в списке отсутствуют

### Requirement: Неназначенную задачу можно взять себе

Сотрудник без права управления задачами SHALL иметь возможность назначить исполнителем себя — и только себя — на задачу без исполнителя. После этого он исполнитель и редактирует задачу по обычным правилам. Остальные изменения неназначенной задачи, автором которой он не является (статус, вложения, поля, назначение другого сотрудника), SHALL отклоняться, пока он её не взял.

#### Scenario: Сотрудник берёт системную задачу

- **WHEN** сотрудник без права управления задачами назначает себя исполнителем системной задачи без исполнителя
- **THEN** он становится исполнителем, автор задачи остаётся системным

#### Scenario: Назначить другого нельзя

- **WHEN** сотрудник без права управления задачами назначает исполнителем другого сотрудника на неназначенную задачу, автором которой не является
- **THEN** операция отклоняется

#### Scenario: Сменить статус без взятия нельзя

- **WHEN** сотрудник без права управления задачами меняет статус неназначенной задачи, автором которой не является
- **THEN** операция отклоняется

#### Scenario: Взятую задачу можно редактировать

- **WHEN** сотрудник взял системную задачу и меняет её статус на «Выполнена»
- **THEN** статус сохранён

### Requirement: Задачу может создать система

Задача SHALL допускать отсутствие автора-сотрудника: такая задача создана системой. Список и карточка задачи SHALL отдавать для неё признак системного автора вместо сотрудника.

#### Scenario: Карточка системной задачи

- **WHEN** запрашивается карточка задачи, созданной системой
- **THEN** карточка отдана без ошибки, автор — система

#### Scenario: Задача сотрудника не становится системной

- **WHEN** запрашивается задача, автором которой был сотрудник
- **THEN** автор отдан как этот сотрудник
