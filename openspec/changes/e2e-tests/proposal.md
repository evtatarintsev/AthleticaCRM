# Proposal

## Why

Сервер покрыт юнит- и DB-тестами (TestContainers), веб — vitest. Но продукт ни разу не проверяется в той сборке, которая уходит на стенд: поднять всё вместе и пройти ключевые пути сейчас можно только руками. Поэтому незамеченным остаётся то, что ломается только в связке контейнеров. Например:

- маршрутизация `prod.conf.template` и проксирование `/api/`;
- HttpOnly-cookie с `SameSite=Strict` и путь refresh-токена;
- миграции Liquibase на чистой базе;
- presigned-ссылки RustFS через `MINIO_PUBLIC_ENDPOINT`;
- отправка писем;
- secure context для фронта.

Ни один из существующих тестов эти места не трогает.

## What Changes

- Новый каталог `e2e/`, отдельный npm-пакет на Playwright. В нём смоук-сценарии двух видов:
  - браузерные, через собранный фронт;
  - API-сценарии, через `request` того же Playwright.
- Стенд e2e — это `docker-compose.prod.yaml` с наложенным `e2e/stand/docker-compose.e2e.yaml`:
  - образы те же, что уходят в прод;
  - nginx работает с **боевым** `prod.conf.template` на самоподписанном сертификате для домена `e2e.test`;
  - Mailpit вместо внешнего SMTP;
  - ЮKassa в тестовом режиме, AI-помощник и прокси Telegram выключены;
  - наружу не публикуется ни один порт;
  - Playwright работает контейнером в той же сети compose.
- Каждый сценарий регистрирует свою организацию с уникальным email. Тесты не чистят базу и могут идти параллельно.
- Начальный набор сценариев:
  1. регистрация → кабинет;
  2. вход и выход;
  3. подтверждение email по письму;
  4. сброс пароля по письму;
  5. справочники → группа → клиент в группе;
  6. занятие и отметка посещения;
  7. продажа абонемента и оплата → баланс клиента;
  8. сотрудник получает доступ письмом и входит с ограниченными правами;
  9. загрузка файла через presigned-ссылку;
  10. API-смоук: здоровье стенда и отказ без сессии.
- Локальный запуск одной командой: `mise run e2e`. Она собирает образы из рабочей копии, поднимает стенд, прогоняет тесты и гасит стенд.

Вне объёма:
- Запуск в CI: гейт перед `deploy`, перенос тега `latest` после зелёного прогона, ручной `workflow_dispatch`, прогоны на PR. Это отдельное изменение, когда набор станет стабильным и будет понятна его длительность. `.github/workflows/` и `DEPLOY.md` здесь не меняются.
- Визуальная регрессия (скриншот-сравнение).
- Нагрузочные тесты.
- Реальные внешние интеграции: ЮKassa-оплата баланса организации, Telegram, AI-провайдер.
- Сценарии, зависящие от «сегодня» и течения времени: продления, «заканчивается», списания по расписанию. Часы стенда не подменяются, это остаётся DB-тестам с `now` из `XxxQuery`.
- Мобильное приложение (`composeApp`).

## Capabilities

### New Capabilities
- `end-to-end-testing`: проверка собранного продукта на полном стенде. Охватывает:
  - состав стенда и его отличие от прода;
  - изоляцию данных сценариев;
  - обязательный набор смоук-сценариев;
  - локальный запуск.

### Modified Capabilities
Нет. Поведение продукта для пользователей не меняется.

## Impact

- **Новое**:
  - `e2e/`: `package.json`, `playwright.config.ts`, `tsconfig.json`, фикстуры, сценарии;
  - `e2e/stand/`: compose-оверлей, `e2e.env` с тестовыми значениями, скрипт генерации сертификата.
- **mise.toml**: задача `e2e`.
- **Документация**: `e2e/README.md`, ссылка в `CLAUDE.md` (команды запуска и правило «новый ключевой сценарий — новый e2e»).
- **server / web / shared**: изменений нет. e2e импортирует `web/src/i18n/ru.ts` (тексты для селекторов) и `web/src/api/generated/contracts.ts` (zod-схемы для API-сценариев) только на чтение.
- **docker-compose.prod.yaml, prod.conf.template**: не меняются. Оверлей переопределяет образы, тома и порты.
- **Зависимости**: `@playwright/test` (только в `e2e/`), образ `mcr.microsoft.com/playwright`, образ `axllent/mailpit`.
