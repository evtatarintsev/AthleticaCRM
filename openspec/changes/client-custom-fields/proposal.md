# Proposal

## Why

Дополнительные поля профиля клиента (`domain/customfields`, раздел настроек «Дополнительные атрибуты клиента») реализованы до перехода на OpenSpec и не описаны ни в одной спецификации: правила типов, ключей, обязательности и проверки значений существуют только в коде. Кроме того, изменение набора полей не попадает в журнал действий — `DbCustomFieldDefinitions` подключён без аудит-декоратора, хотя соседние справочники (источники клиентов, метки посещаемости, тарифы) логируются.

## What Changes

- Новая спецификация `client-custom-fields`, восстановленная по текущему коду: типы полей и их ограничения, машинный ключ, обязательность, порядок, сохранение набора целиком, проверка значений при создании, редактировании и импорте клиента, показ в карточке, списке и CSV-экспорте.
- Новое поведение: каждое добавление, изменение и удаление определения поля записывается в журнал действий (`CREATE` / `UPDATE` / `DELETE`, тип сущности `custom_field`) со снимком определения; в журнале субъект показан названием поля и ведёт в раздел настроек дополнительных полей.
- Для стабильного субъекта в журнале сохранение набора перестаёт пересоздавать строки: неизменённые и изменённые поля сохраняют свой идентификатор (сейчас `DELETE` + `INSERT` на каждое сохранение). Внешний API (`/custom-fields/list`, `/custom-fields/save`) не меняется.

Вне рамок (зафиксировано в design как открытые вопросы): проверка прав на изменение набора полей, ограничение допустимых `entityType`, использование флагов `isSearchable` / `isSortable` в поиске и сортировке.

## Capabilities

### New Capabilities
- `client-custom-fields`: дополнительные поля профиля клиента — определения, проверка значений, отображение и аудит изменений определений.

## Impact

- `server/.../domain/customfields/`: upsert вместо пересоздания строк, новый декоратор `AuditCustomFieldDefinitions`, подключение в `Di.kt`.
- `server/.../read/audit/DbActivityLogView.kt`, `i18n/Messages.kt`: название субъекта `custom_field`.
- `web/src/settings/audit/AuditLogPage.tsx`, словари `ru.ts` / `en.ts`: ссылка на панель `client-additional-attributes`.
- Миграции БД не требуются (уникальность `(org_id, entity_type, field_key)` уже есть).
