# Design

## Context

См. мотивацию в `proposal.md`. В `SessionDetailPage.tsx` ссылка состоит из `Button` с `asChild`, `Link`, `ArrowLeftIcon` и перевода `action.back`, но отрисовывается только внутри загруженного `SessionJournalCard`. У группы отдельные ранние возвраты для загрузки и ошибки, у клиента — общая ветка без данных. Смена вкладок управляется роутером и уже имеет отдельный контракт истории браузера.

Небольшой общий дизайн нужен для согласованного изменения трёх модулей: клиентов, групп и занятий.

## Goals / Non-Goals

**Goals:** переиспользовать существующую ссылку и оформление; сделать навигацию независимой от результата запроса карточки; сохранить нативную семантику ссылки и типизацию маршрута.

**Non-Goals:** общий каркас страниц, хлебные крошки, дополнительные настройки ссылки, механизм запоминания исходного списка или изменение истории вкладок.

## Decisions

### Общий компонент с одним параметром

Добавить `web/src/ui/BackLink.tsx` с единственным параметром `to`, ограниченным маршрутами `/clients`, `/groups`, `/schedule`. Сохранить `Button variant="ghost" size="sm" asChild`, стрелку с `aria-hidden`, перевод `action.back` и существующий видимый фокус. Указывать пустые search-параметры явно, чтобы вкладка карточки не попадала в адрес списка.

Копирование разметки в каждую страницу проще локально, но создаёт несколько мест для дальнейших изменений оформления. Универсальная навигационная обёртка с настройками текста и истории здесь не нужна.

### Ссылка присутствует в каждой ветке отображения

В карточках группы и клиента добавить `BackLink` перед заголовком либо содержимым загрузки/ошибки во всех существующих ветках возврата. Сохранить текущую структуру страниц; не выносить их содержимое в новые компоненты ради одной ссылки.

В занятии заменить существующую разметку в `SessionJournalCard` на `BackLink`, добавить его в ветки загрузки и ошибки `SessionDetailPage`. На странице должна быть ровно одна ссылка возврата. Сохранить вертикальный отступ между ссылкой и содержимым во всех состояниях.

### Переход по фиксированному маршруту

Использовать `Link`, а не `history.back()` или `navigate(-1)`: предыдущей записи может не быть, либо она может вести на другую вкладку, группу или занятие. Обычный переход, открытие в новой вкладке и управление клавиатурой сохраняются средствами существующего компонента ссылки.

### Проверки в существующих тестах страниц

Использовать `openApp` и имеющиеся поддельные серверы. Для каждой страницы проверить единственную ссылку с именем «Назад», её адрес и фактический переход. Отдельно удержать ответ запроса карточки до проверки загрузки и вернуть ошибку для проверки доступности возврата. Для клиента и группы проверить переход после переключения вкладки при прямом открытии карточки. Не добавлять тестовый слой или параметры в production API ради этих проверок.

Клавиатурный переход проверить средствами Testing Library; расположение и видимый фокус — короткой визуальной проверкой. Существующий тест браузерного возврата между вкладками группы должен продолжить проходить.

## Risks / Trade-offs

- Ссылка может пропасть в одной из ранних веток или появиться дважды у занятия → проверять единственность и наличие во всех трёх состояниях каждой страницы.
- Разные отступы у загрузки, ошибки и карточки → сохранить оформление ссылки занятия и проверить узкий и широкий экран.
- Фиксированный маршрут не восстанавливает фильтры списка → это согласованная граница задачи; браузерная история остаётся доступна отдельно.

## Migration Plan

Изменение поставляется с обычным обновлением веб-клиента, без миграций данных и конфигурации. Откат — возврат изменений компонента, страниц и тестов.
