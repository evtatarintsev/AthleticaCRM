## Why

Часть бизнес-правил выполняется только при вызове из конкретного HTTP-маршрута, сценария, планировщика или формы. Прямой вызов доменного метода может обойти проверку или получить другой результат, а сбой при пополнении после подтверждения платежа может оставить платёж оплаченным без зачисления.

## What Changes

- Перенести проверку времени в создание и перенос занятия. Сделать результат `Sessions.new` обязательным и сохранить существующее преобразование `sessions_pkey` в `SESSION_ALREADY_EXISTS` через `onViolation`.
- Проверять сумму до обращения к платёжному шлюзу. Выполнять подтверждение и зачисление атомарно, отдельно обрабатывать повторное уведомление.
- Закрепить в доменных командах переходы клиента и абонемента, условия автоматического списания и погашения долга, правила назначения ролей и филиалов.
- Использовать календарь организации при изменении и синхронизации расписания. Перепроверять срок и настройки при создании задачи по незакрытому журналу.
- Применять правила отправки сообщений на доменных входах.
- Проверять условия тарифов и абонементов, определения и значения кастомных полей, обязательные имена и заголовки при записи.
- Сохранить формы запросов и ответов. Операции, которые уже отклоняются, сохраняют свои доменные коды. Некоторые ранее принимаемые некорректные записи будут отклоняться.

## Capabilities

### New Capabilities

- `domain-write-validation` — серверные правила записи для клиентов, сотрудников, исходящих сообщений, тарифов, кастомных полей и обязательных имён и заголовков.
- `organization-payment` — положительная сумма платежа, атомарное подтверждение и зачисление, обработка повторного уведомления.

### Modified Capabilities

- `group-schedule` — дата вступления в силу относительно календаря организации.
- `session-generation` — единая дата организации для сверки при изменении расписания и состава тренеров; проверка времени и уникальности при ручном создании и переносе занятия.
- `membership-lifecycle` — проверка условий при выдаче абонемента. Перенос существующих переходов в домен сохраняет их правила.
- `membership-debits` — погашение долга отклоняется целиком при недопустимом занятии, повторы в выборе учитываются один раз.
- `attendance-control` — срок и настройки перепроверяются при создании задачи по незакрытому журналу.

Дополнительные изменения `inbound-triage` и `channel-settings` вынесены за рамки change по результатам проверки 10.1.

## Impact

- Серверные доменные команды, HTTP-маршруты, фоновые обработчики, декораторы аудита и доменные тесты. Изменение типа результата `Sessions.new` требует обновить внутренние вызовы.
- Текущий контракт ошибок БД уже поставлен в PR #198. `QueryBuilder.onViolation` преобразует только зарегистрированные ограничения, остальные идут через `ConstraintViolation` в `Raise<AppError>`. Повторная миграция репозиториев не требуется.
- UI сохраняет быстрые проверки для обратной связи. `shared` затрагивается там, где уже живут используемые доменные типы, например `CustomFieldValues`.
