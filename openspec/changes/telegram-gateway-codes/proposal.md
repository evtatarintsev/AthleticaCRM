## Why

Вход в клиентское приложение (`client-mobile-app`) — по одноразовому коду, и код в первую
очередь отправляется в Telegram: это дешевле SMS и не зависит от доставки операторами. Ядро
определяет порт `VerificationCodeSender` и до этого изменения работает с заглушкой, поэтому
без настоящего отправителя приложение в production не включить.

## What Changes

- Отправитель кодов канала `TELEGRAM` на Telegram Gateway API: код приходит в Telegram по
  номеру телефона, без бота и без предварительного контакта с человеком.
- Перед отправкой проверяется, может ли Telegram доставить сообщение на номер; если нет —
  ядро сразу переходит на SMS.
- Сообщение в Telegram живёт столько же, сколько код (5 минут).
- Ключ Gateway API — в конфигурации; запросы идут через прокси Telegram, если он настроен.
- **Не входит**: отчёты о доставке через callback (позднюю недоставку закрывает кнопка
  «Отправить по SMS» в приложении), проверка кода силами Telegram (код проверяет ядро).

## Capabilities

### New Capabilities
- `client-app-code-telegram`: доставка кода входа клиентского приложения в Telegram по номеру
  телефона и сообщение о недоставляемом номере.

## Impact

- **server**: `infra/telegram/gateway/` — HTTP-клиент Gateway API и реализация
  `VerificationCodeSender`; подключение в `Di.kt` вместо заглушки канала `TELEGRAM`.
- **Конфигурация**: токен Gateway API в `application.conf`, `docker-compose.prod.yaml`,
  `.env.prod.example`.
- **Внешние зависимости**: Telegram Gateway API (платный, баланс пополняется в кабинете Gateway).
- **Зависимости**: порт `VerificationCodeSender` из `client-mobile-app` (задача 1.2). Остальное
  ядро не нужно: адаптер разрабатывается и тестируется на заглушке HTTP-сервера.
