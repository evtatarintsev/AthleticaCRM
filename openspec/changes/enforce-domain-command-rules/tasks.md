## 1. Платежи (п. 3–4, первыми: денежный баг)

- [ ] 1.1 Подтверждение платежа: `Left` из `markAsPaid` + `replenish` поднимать из `db.transaction`, чтобы транзакция откатывалась; `PaymentAlreadyProcessed` обрабатывать снаружи как допустимый повтор с ответом 200. Тест: при отказе `replenish` (например, `BALANCE_CURRENCY_MISMATCH`) платёж остаётся `pending`, записи в журнале баланса нет; повторный webhook не даёт второго зачисления
- [ ] 1.2 Вынести составную команду подтверждения из `CheckoutRoutes` в сценарий; в маршруте оставить подпись, разбор события и HTTP-ответ. Проверка: тесты 1.1 вызывают сценарий напрямую
- [ ] 1.3 Инициация платежа: проверять положительную сумму до `paymentGateway.createPayment` тем же правилом, что в `Payments.create`. Тест: ноль и минус отклоняются без вызова шлюза; `PaymentGatewayError` по-прежнему поднимается через `Raise`

## 2. Занятия (п. 1–2)

- [ ] 2.1 Проверку `INVALID_SESSION_TIME` перенести в `DbSessions.new` и `DbSession.reschedule`, удалить из `CreateSession` и `RescheduleSession`; `CHECK` в БД оставить. Тест: равный и обратный интервал отклоняются при прямом доменном вызове обоих входов
- [ ] 2.2 Сделать результат `Sessions.new` обязательным (`Session`) в `Sessions`, `DbSessions`, `AuditSessions`; удалить `?: raise(SESSION_ALREADY_EXISTS)` в `CreateSession`. Тест: повторный ID даёт `SESSION_ALREADY_EXISTS` без записи аудита, созданное занятие возвращается с тренерами
