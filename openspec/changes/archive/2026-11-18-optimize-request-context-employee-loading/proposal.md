# Proposal

## Why

Перед каждым защищённым обработчиком сервер загружает сотрудника пятью последовательными SELECT, а `assistant/status` повторяет эту загрузку. При параллельной загрузке экрана накладные расходы умножаются; issue [#229](https://github.com/evtatarintsev/AthleticaCRM/issues/229) требует сократить обращения к БД с сохранением актуальности прав и проверить эффект на прогретом приложении.

## What Changes

- `Employees.byId/byIds` загружают сотрудника, назначенные роли с их правами, персональные выдачи/отзывы и доступ к филиалам одним SQL statement для непустого набора ID. Кэш сотрудников или прав в этом change не вводится; спека фиксирует только видимость изменений в следующем запросе, а число statements — design и тесты.
- Сохраняются изоляция организаций, все права владельца, приоритет персонального запрета, доступ ко всем либо выбранным филиалам и ошибка `EMPLOYEE_NOT_FOUND`. Пустой `byIds` не обращается к БД, повторяющиеся ID не дублируют результат, отсутствие хотя бы одного уникального ID отклоняет загрузку целиком.
- `assistant/status` вычисляет `permitted` по сотруднику из контекста текущего запроса без повторного чтения. Это снимок на момент сборки контекста; следующее HTTP-обращение заново читает актуальные данные. Формат ответа и чтение настроек помощника сохраняются.
- Перечитывание сотрудника перед командами помощника после ожидания модели и проверки владельца при управлении настройками сохраняются.
- Регрессионные проверки фиксируют число SQL и поведение доступа; замер времени сборки контекста до/после на прогретом приложении.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `employee-permissions`: полнота загрузки доступа сотрудника, видимость изменений доступа в следующем запросе и сохранение пакетной семантики загрузки.
- `ai-assistent`: статус по контексту текущего запроса; требование «Доступ сотрудника и управление настройками» дополнено явной повторной проверкой перед командами после ожидания модели.

## Impact

- `server/.../domain/employees/DbEmployees.kt`: общая загрузка и отображение связанных данных в существующие доменные объекты. `DbRoles` остаётся каталогом ролей для остальных операций; загрузка сотрудника больше не читает весь каталог.
- `server/.../assistant/AssistantService.kt`: только устранение повторного чтения в `status`; `access` и `requireOwner` сохраняют своё назначение.
- `RouteWithContext.contextFromRequest`, `DbAuth`, операции сотрудников, групп, занятий, задач и уведомлений, а также декораторы `AuditEmployees`/`EmailEmployees` остаются вызывающими прежний интерфейс и входят в проверку совместимости.
- Тесты `DbEmployeesTest`, `AssistantServiceTest`, `AssistantRoutesTest` и существующий `AssistantGuardTest`; результаты замера сохраняются в `measurements.md` change.
- Без изменений HTTP-контрактов, новых зависимостей, миграций, кэша прав, изменений пула и границ транзакций. Конкретное сокращение задержки в миллисекундах не обещается.
