# Proposal

## Why

Сервер не хранит выданные токены: выход только чистит cookie, а украденный refresh-токен работает
30 дней. Пользователь не видит, где он вошёл, и не может завершить чужой вход. Блокировка сотрудника
отсекает доступ проверкой `blocked_at`, но после разблокировки все старые refresh-токены снова
становятся действительными.

## What Changes

- Вход создаёт серверную сессию. Её идентификатор (`sid`) кладётся в access- и refresh-токен.
  Отозвать сессию = удалить её запись.
- Защищённый запрос и обновление токена принимаются, только если сессия `sid` существует. Отзыв
  срабатывает со следующего запроса, без ожидания истечения access-токена.
- Refresh-токен ротируется при каждом обновлении. Если предъявлен устаревший токен (вне короткого
  окна на гонку вкладок), сессия завершается целиком: это признак кражи.
- Смена филиала выпускает новые токены в рамках той же сессии.
- Выход удаляет текущую сессию на сервере.
- Блокировка сотрудника завершает все его сессии.
- Смена пароля завершает все сессии пользователя, кроме текущей.
- Новый экран «Активные сеансы» в профиле пользователя: «Это устройство», «Завершить все другие
  сеансы», список остальных сеансов с кнопкой завершения. Устройство описывается как
  «браузер · ОС» по User-Agent, плюс IP и время последней активности.
- Тот же список сеансов в карточке сотрудника. Завершать их может тот, кто может блокировать
  этого сотрудника (не владельца и не себя).
- Связь пользователь ↔ сотрудник становится строго один к одному: `employees.user_id` уникален.
- **BREAKING**: токены без `sid` не принимаются. После выката все пользователи входят заново.

Вне рамок: определение города по IP, переименование устройства, фоновая чистка устаревших сессий.

## Capabilities

### New Capabilities

- `auth-sessions`: серверные сессии входа, отзыв токенов, ротация refresh-токена, завершение
  сессий пользователем, при блокировке сотрудника и смене пароля.
- `web-client/active-sessions`: экран активных сеансов в профиле пользователя и список сеансов
  в карточке сотрудника.

### Modified Capabilities

- `web-client/app-shell`: выход завершает сессию на сервере так, что прежние токены больше
  не принимаются; отозванная сессия ведёт на страницу входа так же, как истёкшая.
- `admin-cli`: из сброса пароля убран сценарий «пользователь — сотрудник нескольких организаций»,
  такой пользователь больше невозможен.

## Impact

- БД: новая таблица `auth_sessions`; уникальный индекс `employees(user_id)` вместо
  `(user_id, org_id)`.
- `security/JwtConfig`: claim `sid` в обоих токенах, claim `jti` в refresh-токене.
- `routes/AuthRoutes`, `routes/RouteWithContext.contextFromRequest`: создание, проверка, ротация
  и удаление сессий; `EmployeeRequestContext` получает идентификатор текущей сессии.
- `domain/auth/DbAuth` (logout, changePassword), `domain/employees/DbEmployee.block()`.
- Новые маршруты списка и завершения сеансов. Схемы в `shared`, регенерация
  `web/src/api/generated/contracts.ts`.
- Web: `web/src/account` (новая панель сеансов), `web/src/employees/EmployeeCardSheet.tsx`,
  словари `ru.ts` / `en.ts`.
- Дополняет незавершённый change `employee-access-and-presence` (блокировка): его требования
  не меняются.
