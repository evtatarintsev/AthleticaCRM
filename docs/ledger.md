# Главная книга

Деньги клуба учитываются двойной записью. Каждое событие — неизменяемая строка
`ledger_transactions` и не менее двух ненулевых `ledger_postings` с общей суммой ноль.
Валюта проводок — валюта организации; суммы в Kotlin представлены `Money`.
Остаток на дату — сумма проводок по счёту с `occurred_on` не позже этой даты.

## Счета и знаки

Дебет записывается плюсом, кредит — минусом. Положительный остаток кассы — деньги клуба,
положительный остаток `receivable` — долг клиента по продаже, отрицательный остаток
`advance` — аванс клиента. Видимый баланс клиента = `-SUM(amount)` по его счетам
`advance` и `receivable`, то есть аванс минус долги.

| Вид | Владелец |
| --- | --- |
| `cash` | Касса |
| `advance` | Клиент |
| `receivable` | Продажа и её клиент |
| `income`, `expense` | Статья доходов или расходов |
| `revenue`, `adjustment`, `opening` | Организация, один счёт каждого вида |

Счета создаются лениво. Ограничения владельцев, организации и уникальности проверяет БД.
Команды оплаты, возврата, выплаты и отмены продажи сначала блокируют клиента, затем
соответствующие счета аванса и долга в порядке `id`.
Денег в кассе может быть меньше нуля. Только административная корректировка допускает
отрицательный аванс; остальные операции проверяют итоговый аванс под блокировкой.

## Шаблоны проводок

| Событие | Проводки |
| --- | --- |
| Продажа S | `receivable +S`, `revenue -S` |
| Пополнение аванса C | `cash +C`, `advance -C` |
| Оплата кассами C и авансом A при долге D | `cash +C`, `receivable -min(C+A,D)`, `advance +(A-max(C+A-D,0))` |
| Возврат R | `revenue +R`, `receivable -min(R,D)`, `advance -max(R-D,0)` |
| Выплата X | `advance +X`, `cash -X` |
| Корректировка видимого аванса X | `advance -X`, `adjustment +X` |
| Прочий приход X | `cash +X`, `income -X` |
| Расход X | `cash -X`, `expense +X` |
| Перевод X | `cash(to) +X`, `cash(from) -X` |
| Начальный остаток X | `cash +X`, `opening -X` |

Нулевые части шаблона не записываются. Бесплатная продажа не создаёт транзакцию.
Оплата может включать несколько касс. Кассовая переплата зачисляется на аванс;
часть с аванса не превышает ни доступного аванса, ни долга продажи. `advance_used`
сохраняет исходную часть оплаты с аванса: её нельзя восстановить из свёрнутой проводки
при одновременной кассовой переплате.

Кассовая проводка содержит статью ДДС, кроме перевода и ввода остатков. Оплаты и
выплаты используют неизменяемые системные статьи `client_receipts` и `client_refunds`.
Остальные статьи имеют не более двух уровней, направление и архив вместо удаления.

## Продажи и отмена

После возврата по продаже отдельная отмена её оплаты запрещена: возврат уже распределил деньги
между долгом, авансом и выплатой. Ошибочную продажу можно отменить целиком по правилам ниже.

Продажа хранит позиции и автора. Абонемент ссылается на позицию продажи; цена читается
из `sale_items.amount`. Выдача, продажа и необязательная оплата записываются в одной
транзакции БД. При отказе не остаётся ни одного из документов.

Исправление денежных событий — только сторно с обязательной причиной. Оно содержит
обратные проводки и уникальную ссылку `reverses_id`, получает сегодняшнюю дату
организации. Сторно нельзя отменить. Обновление и удаление проводок и транзакций
запрещены триггерами; отложенные триггеры проверяют баланс и статью при коммите.

Отмена продажи сторнирует все её действующие денежные операции и отзывает абонементы;
уже отозванный абонемент пропускается. Если отзыв недопустим (есть списания, абонемент закрыт)
или итоговый аванс стал бы отрицательным, вся операция откатывается.
Возврат продажи сначала уменьшает долг, затем зачисляет аванс; выплата из кассы может
выполняться вместе с возвратом в одной транзакции и выплачивает только зачисленную на аванс
часть: погашенный возвратом долг деньгами не возвращается.

Направление и признак группы у статьи, по которой уже были движения, не меняются:
иначе ДДС прошлых периодов сменил бы знак или разнёс суммы на группу.

## Права и филиалы

- `CAN_ACCEPT_PAYMENTS`: оплаты продаж и пополнение аванса, отмена своих оплат,
  записанных сегодня в часовом поясе организации.
- `CAN_MANAGE_FINANCE`: кассы, статьи, приходы, расходы, переводы, выплаты, возвраты,
  корректировки и отмена операций организации.
- `CAN_VIEW_FINANCE`: журнал, остатки касс и ДДС.
- `CAN_VIEW_CLIENT_BALANCE`: история баланса клиента.

Продажа без оплаты отдельного финансового права не требует. Касса без филиала доступна
сотрудникам с финансовыми правами; касса филиала — только при доступе к этому филиалу.
Записи всех таблиц и проекции ограничиваются организацией текущего сотрудника.

## ДДС и журнал

Кассовый журнал показывает исходную операцию один раз с признаком и причиной отмены,
без отдельной строки сторно. Его итоги исключают отменённые операции.

ДДС отражает исходные проводки и сторно по их собственным датам. Расход октября,
отменённый в ноябре, остаётся расходом октября и уменьшает расходы ноября. Исторические
остатки не пересчитываются. Внутренние переводы выбранных касс взаимно гасятся;
переводы за границу выборки идут строкой «Перемещения», ввод остатков — отдельной
строкой. Продажи без движения касс и корректировки в ДДС не входят.

Миграция 0086 удаляет тестовые абонементы и старый журнал баланса. Обратной миграции
нет: откат требует восстановления базы из резервной копии и отката приложения.
