## Why

Клиент кабинета (`client-cabinet-web`) видит своё расписание и баланс, но с вопросом
(«можно продлить заранее?», «вот справка от врача») по-прежнему идёт в мессенджер
администратора. Переписка из приложения, попадающая в единые «Входящие», убирает этот обход
и не требует от клуба отдельного мессенджера.

## What Changes

- Встроенный канал «Приложение» у каждой организации с включённым приложением: не
  настраивается и не виден в списке каналов, адрес — подключённый номер клиента.
- Человек пишет организации из приложения по выбранному клиенту; сообщение попадает в беседу
  клиента и во «Входящие».
- Сотрудник отвечает из беседы, выбрав канал «Приложение» и подключённый номер.
- Переписка отдельна для каждого номера: папа не видит ответов маме.
- Вложения — изображения и PDF до 10 МБ — с обеих сторон.
- Непрочитанные для клиента: счётчик по профилю и последнее непрочитанное на главной.
- О новом сообщении ставится push через порт `ClientAppPushes`; доставку делает `client-app-push`.
- **Не входит**: экраны приложения (в `client-mobile-android`), отправка push (в
  `client-app-push`), сообщения из других каналов в приложении.

## Capabilities

### New Capabilities
- `client-app-chat`: переписка человека из мобильного приложения с организацией по выбранному
  клиенту как канал единых «Входящих».

## Impact

- **shared**: `ChannelConfig.ClientApp`, схемы переписки клиентского API.
- **server**: транспорт канала, встроенная интеграция при включении приложения, проекции
  `read/clientapp/chat/*`, маршруты `/api/client-app/chat/*`, вложения сообщений, выбор номера
  при ответе во «Входящих».
- **web**: «Приложение» в выборе канала ответа, вложения в беседе; перегенерация контрактов.
- **БД**: вложения сообщений, прочитанность для клиента.
- **Зависимости**: `client-cabinet-web` — доступы, `ClientProfileContext` и проверка доступа в
  SQL (задачи 2.x, 4.4), включение кабинета (5.1), порт `ClientAppPushes` (1.1).
