# Spec Delta

## Purpose

ФИО клиента: из каких частей оно состоит, что обязательно, как система показывает клиента и как
упорядочивает клиентов «по имени».

## ADDED Requirements

### Requirement: Части ФИО клиента

Клиент SHALL хранить фамилию, имя и отчество раздельно. Фамилия и имя SHALL быть обязательны,
отчество SHALL быть необязательным. Каждая часть SHALL сохраняться без пробелов по краям. Пустая
или состоящая из пробелов фамилия или имя SHALL отклоняться доменной ошибкой, отчество из пробелов
SHALL сохраняться как отсутствующее.

#### Scenario: Полное ФИО

- **WHEN** сотрудник создаёт клиента с фамилией « Иванов », именем «Пётр» и отчеством «Сергеевич»
- **THEN** клиент сохраняется с фамилией «Иванов», именем «Пётр» и отчеством «Сергеевич»

#### Scenario: Без отчества

- **WHEN** сотрудник создаёт клиента с фамилией «Смирнова» и именем «Анна» без отчества
- **THEN** клиент сохраняется, отчества у него нет

#### Scenario: Нет фамилии

- **WHEN** запрос на создание клиента передаёт имя «Пётр» и пустую фамилию
- **THEN** запрос отклоняется, клиент не создаётся

#### Scenario: Отчество из пробелов

- **WHEN** сотрудник сохраняет клиента с отчеством из пробелов
- **THEN** у клиента нет отчества

### Requirement: Отображаемое имя клиента

Везде, где система показывает клиента одной строкой (списки, журнал, касса, задачи, переписка,
выгрузка), SHALL использоваться отображаемое имя «Фамилия Имя Отчество»: непустые части через
один пробел. Отображаемое имя SHALL вычисляться из частей ФИО и SHALL NOT редактироваться
отдельно.

#### Scenario: С отчеством

- **WHEN** у клиента фамилия «Иванов», имя «Пётр», отчество «Сергеевич»
- **THEN** клиент показывается как «Иванов Пётр Сергеевич»

#### Scenario: Без отчества

- **WHEN** у клиента фамилия «Смирнова», имя «Анна», отчества нет
- **THEN** клиент показывается как «Смирнова Анна»

### Requirement: Порядок по имени

Сортировка клиентов по полю `NAME` SHALL упорядочивать по фамилии, при равной фамилии по имени,
затем по отчеству (клиент без отчества раньше клиента с отчеством). Остальные правила сортировки
из `client-list-sorting` SHALL сохраняться.

#### Scenario: Одинаковая фамилия

- **WHEN** в списке «Иванов Сергей», «Иванов Пётр» и «Алексеева Мария», сортировка по имени по
  возрастанию
- **THEN** порядок: «Алексеева Мария», «Иванов Пётр», «Иванов Сергей»

### Requirement: Поиск по частям ФИО

Поиск в списке клиентов SHALL находить клиента по подстроке отображаемого имени без учёта
регистра, в том числе по фамилии, по имени или по «фамилия имя».

#### Scenario: Поиск по имени

- **WHEN** у клиента «Иванов Пётр Сергеевич» сотрудник ищет «пётр»
- **THEN** клиент «Иванов Пётр Сергеевич» найден

#### Scenario: Поиск по фамилии и имени

- **WHEN** сотрудник ищет «Иванов Пётр»
- **THEN** клиент «Иванов Пётр Сергеевич» найден
