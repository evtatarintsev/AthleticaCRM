# Spec Delta

## ADDED Requirements

### Requirement: Полная загрузка доступа сотрудника

Загрузка сотрудника SHALL возвращать его данные, назначенные роли с правами каждой роли, персональные выдачи и отзывы и доступ к филиалам без потерь и без дублирования назначений. Роль без прав SHALL оставаться в наборе ролей сотрудника.

#### Scenario: Сотрудник с несколькими назначениями

- **WHEN** загружается сотрудник с несколькими ролями, персональными правами и выбранными филиалами
- **THEN** загруженные данные содержат права каждой назначенной роли, персональные выдачи и отзывы и набор доступных филиалов без потерь или дублирования назначений

#### Scenario: Сотрудник без назначенных ролей

- **WHEN** загружается сотрудник без ролей и персональных прав
- **THEN** он возвращается с пустым набором ролей и действующими правами по существующим правилам, включая особый статус владельца
- **AND** отсутствие назначений не исключает сотрудника из результата

### Requirement: Актуальный доступ в последующих запросах

Изменения сотрудника и его доступа, зафиксированные до начала защищённого HTTP-запроса, SHALL учитываться при проверках этого запроса без повторного входа. Это SHALL сохранять правила прав владельца, приоритет персонального отзыва и различие доступа ко всем и выбранным филиалам.

#### Scenario: Изменены права назначенной роли

- **WHEN** права назначенной сотруднику роли изменены и транзакция изменения завершена до следующего запроса
- **THEN** следующий запрос проверяет права с учётом изменённой роли без повторного входа

#### Scenario: Изменены персональные права

- **WHEN** персональные выдачи или отзывы сотрудника изменены до следующего запроса
- **THEN** следующий запрос использует новый набор прав с приоритетом персонального запрета для обычного сотрудника
- **AND** владелец продолжает иметь все пользовательские права независимо от персональных отзывов

#### Scenario: Изменён доступ к филиалам

- **WHEN** доступ сотрудника переключён между всеми филиалами и выбранными филиалами либо изменён выбранный набор до следующего запроса
- **THEN** следующий запрос получает новый режим и набор доступных филиалов
- **AND** пустой выбранный набор не означает доступ ко всем филиалам

#### Scenario: Изменена активность сотрудника

- **WHEN** сотрудник деактивирован до следующего запроса
- **THEN** сотрудник в контексте следующего запроса неактивен
- **AND** проверки, требующие активного сотрудника, отклоняют доступ

### Requirement: Совместимость пакетной загрузки сотрудников

Загрузка сотрудников SHALL возвращать каждого запрошенного сотрудника текущей организации один раз независимо от повторов идентификаторов. Для пустого набора система SHALL возвращать пустой результат. Отсутствие любого уникального идентификатора в текущей организации SHALL завершать всю загрузку ошибкой `EMPLOYEE_NOT_FOUND` без частичного результата и раскрытия чужих данных.

#### Scenario: Пустой набор

- **WHEN** запрошена загрузка пустого набора сотрудников
- **THEN** возвращается пустой результат

#### Scenario: Повторяющиеся идентификаторы

- **WHEN** запрошено несколько существующих сотрудников текущей организации с повторениями идентификаторов
- **THEN** каждый сотрудник возвращается один раз с собственными ролями, правами и филиалами

#### Scenario: Часть сотрудников отсутствует или принадлежит другой организации

- **WHEN** запрошенный набор содержит хотя бы один отсутствующий идентификатор либо идентификатор сотрудника другой организации
- **THEN** возвращается `EMPLOYEE_NOT_FOUND` для загрузки целиком без частичного результата
- **AND** данные сотрудников другой организации не возвращаются

#### Scenario: Отсутствует единственный сотрудник

- **WHEN** запрошен один отсутствующий сотрудник либо сотрудник другой организации
- **THEN** возвращается `EMPLOYEE_NOT_FOUND`, как и при пакетной загрузке
