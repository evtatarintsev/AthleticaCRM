## Context

Мотивация — proposal.md. Порт и политика выбора канала — design `client-mobile-app` §1 и §6:
`VerificationCodeSender` с `channel = SMS`, ошибки `CodeDeliveryError.Undeliverable` и `Failed`.
Лимиты по номеру (60 с, 5/час, 10/сутки) — в ядре; здесь только общий предел платформы.

Что есть: `ChannelConfig.SmscSms` и `SmscSmsTransport` для каналов организаций — заглушка без
HTTP. Настоящего клиента SMSC нет.

## Goals / Non-Goals

**Goals:**
- Клиент SMSC, который потом без изменений возьмёт `SmscSmsTransport` каналов организаций.

**Non-Goals:**
- Отчёты о доставке SMS, статусы `deliveries` — для кодов не нужны: человек либо получил код,
  либо запросит новый.
- Несколько провайдеров с переключением.

## Decisions

### 1. Провайдер — SMSC

Каналы организаций уже моделируют SMSC (`ChannelConfig.SmscSms`), поэтому клиент пригодится
дважды. HTTP API: `POST https://smsc.ru/sys/send.php` с `login`, `psw`, `phones`, `mes`,
`sender`, `fmt=3` (JSON-ответ: `id`/`cnt` при успехе, `error`/`error_code` при ошибке).

- *Альтернатива — другой провайдер (SMS.ru, МТС Exolve):* интерфейс отправки один, замена
  затрагивает только `infra/`; выбирать есть смысл по цене, когда будет понятен объём.

### 2. Клиент `SmscApi` в `infra/smsc/`, отправитель — отдельно

`SmscApi(login, password)` — только транспорт: отправить текст на номер, вернуть `id` или ошибку
провайдера. `PlatformSmsCodeSender` поверх него собирает текст из i18n, проверяет суточный
предел и маппит ошибки: ошибки провайдера и сети → `Failed`; предел исчерпан → `Undeliverable`
(для человека это «отправить не удалось», для ядра — канала больше нет).

### 3. Суточный предел — счётчик в БД

Таблица `platform_sms_daily(day date primary key, sent int)`; отправка делает
`INSERT … ON CONFLICT DO UPDATE SET sent = sent + 1 … RETURNING sent` и не отправляет, если
результат больше предела. Счётчик в БД, а не в памяти: сервер может перезапуститься или
работать в нескольких экземплярах. Таблица ни на что не ссылается, поэтому
порядок её миграции относительно ядра не важен.

### 4. Конфигурация

```
platformSms {
    login = ${?PLATFORM_SMS_LOGIN}
    password = ${?PLATFORM_SMS_PASSWORD}
    sender = ${?PLATFORM_SMS_SENDER}
    dailyLimit = 2000
    dailyLimit = ${?PLATFORM_SMS_DAILY_LIMIT}
}
```

Без логина в production SMS-отправитель не подключается, и ядро отвечает человеку, что SMS
недоступны; в `development` остаётся заглушка ядра.

## Risks / Trade-offs

- [Буквенное имя отправителя не зарегистрировано к запуску] → SMSC отправляет с общего
  отправителя; доставляемость хуже, но коды доходят.
- [Предел исчерпан атакой, и настоящие пользователи без SMS] → Telegram остаётся основным
  каналом; предупреждение в журнале — сигнал поднять предел или включить лимиты по IP.
- [Стоимость SMS] → предел ограничивает расход сверху; фактический расход — в кабинете SMSC.
