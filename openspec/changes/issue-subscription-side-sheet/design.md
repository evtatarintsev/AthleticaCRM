## Context

`ClientIssueSubscriptionPage` — отдельная страница на `useForm`. Тариф выбирается из `NativeSelect` (по умолчанию «Индивидуальный»), при выборе условия тарифа копируются в поля, которые можно менять. Валюта берётся из `session.orgInfo.balance?.currency ?? "RUB"`. В выдачу уходят `tariffPlanId` и название выбранного тарифа (для индивидуального — `null` и `clients.detail.subscriptionIndividual`). Ссылка на страницу — `Link` в `ClientCardHeader`.

После `tariffs-side-sheets` в `settings/tariffs/` есть `TariffRow` (строка тарифа без поведения), `tariffTermsText` и `TariffSheet`. `TariffSheet` получает `currency`, `onSave(terms) => Promise<string | null>` и необязательный `onArchiveToggle`, а API вызывает владелец панели. Образец панели с собственным состоянием открытия на карточке клиента — `ClientBalanceSheet`: `useState` в `ClientDetailPage`, адрес не меняется.

`EditSheetForm` сообщает панели `dirty`/`submitting` через `reportGuard` в эффекте без очистки: если форма размонтируется, последнее сообщённое состояние остаётся.

## Goals / Non-Goals

**Goals:**
- Два шага в одной панели, без отдельной страницы и без своего «мастера» в общих компонентах.
- Повторно использовать `TariffRow` и `TariffSheet` без изменения их поведения в настройках.

**Non-Goals:**
- Общий компонент пошаговой панели — шагов два, и сценарий один.
- Синхронизация открытой панели с адресом (`?panel=`): на карточке клиента так не делает и баланс.

## Decisions

### Одна панель, шаг — локальное состояние

```
ClientDetailPage  issueOpen (useState)
  +- IssueSubscriptionSheet (EditSheet md, "Выдать абонемент")
       +- IssueSubscriptionPanel
       |    form = useForm(...)                живёт на обоих шагах
       |    step: pick | terms(template)
       |    pick  -> EditSheetBody: [+ Новый тариф], строки тарифов, "Индивидуальный"
       |    terms -> EditSheetForm (submitLabel "Выдать"): шаблон [Сменить] + поля
       +- TariffSheet (вложенная, md)          create | edit, без onArchiveToggle
```

`step` — `{ kind: "pick" } | { kind: "terms"; template: Template }`, где
`Template = { kind: "tariff"; tariff: TariffPlanSchema } | { kind: "individual" }`. Последний выбранный шаблон хранится отдельно от шага, чтобы на первом шаге подсвечивать его строку и решать, сбрасывать ли форму при повторном выборе.

Альтернатива — второй шаг вложенной панелью поверх первого. Отвергнута: закрытие верхней панели значило бы «назад», а крестик нижней — «отменить всё», и это двусмысленно. Кроме того, панель изменения тарифа стала бы третьим уровнем рядом со вторым шагом.

### Форма поднята в панель, тариф — шаблон

`useForm` создаётся в `IssueSubscriptionPanel` и переживает переход между шагами. Выбор шаблона:
- тот же шаблон, что и выбранный ранее (тот же id тарифа или снова «Индивидуальный»), — форма не трогается;
- другой шаблон — `form.reset(valuesFrom(template))`. Значения шаблона становятся значениями по умолчанию, поэтому `isDirty` после выбора — `false`, и защита срабатывает только на правки, сделанные на втором шаге.

`valuesFrom` заполняет `unlimited`, `sessions`, `durationValue`, `durationUnit`, `price` из тарифа, а для индивидуального — пустыми; `startDate` — сегодня. Схема проверки и разбор чисел и суммы переносятся со страницы без изменений. При отправке `tariffPlanId` и `name` берутся из шаблона, а не из полей — это сохраняет текущее поведение: ссылка на тариф остаётся и при изменённых условиях.

Перед реализацией проверить, что `reset(values)` в используемой версии TanStack Form обновляет `defaultValues` (иначе — передать их явно или пересоздать форму ключом по шаблону с переносом значений).

### Защита несохранённых изменений на обоих шагах

На втором шаге `dirty`/`submitting` сообщает `EditSheetForm`. На первом шаге панель сама вызывает `useEditSheet().reportGuard({ dirty: form.state.isDirty, submitting: false })`. Это закрывает две ловушки: после «Сменить» в панели не остаётся устаревшее состояние размонтированной формы, а правки, которые вернутся при выборе того же шаблона, не теряются молча при закрытии с первого шага.

### Строка выбора — две соседние кнопки

```
+-----------------------------------------------------+
| [ 8 занятий               4 000 RUB ]  [pencil]     |
|   8 зан. * 1 мес.                                    |
+-----------------------------------------------------+
  ^ button: выбрать                ^ button: изменить, aria-label "Изменить 8 занятий"
```

Кнопки не вкладываются друг в друга, поэтому `TariffRow` остаётся содержимым первой кнопки, а иконка изменения — соседней кнопкой в общей рамке. Выбранный шаблон отмечается `aria-current="true"` и рамкой. Отдельной кнопки «Выбрать» нет: нажатие на строку и есть выбор. «Индивидуальный» — такая же строка-кнопка под тарифами, без кнопки изменения.

### Новый тариф сразу выбирается

Владелец `TariffSheet` генерирует id сам (`uuidv7()`), поэтому после успешного `tariffs/create` шаблон собирается из отправленных условий и этого id. Ждать, пока тариф появится в обновлённом `tariffs/list`, не нужно. Затем `TariffSheet` закрывается сама (`useEditSheet().close()`), панель выдачи переходит ко второму шагу и сбрасывает форму по новому шаблону. После `tariffs/update` список инвалидируется, шаг и выбор не меняются. `onArchiveToggle` не передаётся, поэтому блока архива в панели тарифа нет.

### Валюта — из `org/settings`

`TariffSheet` требует валюту, а настройки тарифов берут её из `org/settings`. Панель выдачи делает так же и не использует `session.orgInfo.balance?.currency ?? "RUB"`. Пока настройки не загружены, создание тарифа и кнопка «Выдать» недоступны. Так в организации без баланса стоимость больше не уходит молча в рублях.

### Общий модуль `tariffs/`

`TariffRow.tsx`, `tariffTerms.ts` и `TariffSheet.tsx` переезжают из `web/src/settings/tariffs/` в `web/src/tariffs/`. Ими теперь пользуются настройки и клиенты, и импорт клиентов из `settings/` был бы зависимостью раздела от чужого раздела. `TariffsSheet` остаётся в настройках.

### Маршрут удаляется, кнопка в шапке

Удаляется `clientIssueSubscriptionRoute` из `router.tsx`, без редиректа. `ClientCardHeader` получает `onIssueSubscription: () => void`, и `Link` становится `Button`. Состояние `issueOpen` живёт в `ClientDetailPage`, рядом с `balanceOpen`. После выдачи инвалидируется `memberships/list` клиента, как сейчас. Детальная карточка клиента тоже инвалидируется, потому что от абонементов зависят плитки быстрой информации и предупреждения.

## Risks / Trade-offs

- [Тариф изменён во вложенной панели после того, как был выбран и поправлен на втором шаге] → при повторном выборе того же тарифа форма сохраняет введённые значения и не подтягивает новые условия. Это принято: тариф — шаблон, а введённое пользователем важнее.
- [Изменение тарифа из выдачи меняет его для всей организации] → прав на тарифы нет и в настройках; уже выданные абонементы не затрагиваются, потому что условия копируются в абонемент.
- [Закладки на `/clients/<id>/issue-subscription` перестанут работать] → принято, как для `/settings/tariffs`.
- [Перенос модулей тарифов задевает импорты настроек] → чисто механический перенос, его проверяют `npm run check` и тесты `TariffsSheet`.
