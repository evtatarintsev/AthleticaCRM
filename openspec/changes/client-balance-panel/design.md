## Context

Мотивация — в `proposal.md`. Требования — в `specs/web-client/client-balance/spec.md`.

Сейчас:
- `ClientBalanceSection` — блок ленты `payments`: журнал (`clients/balance/history`) с лимитом
  и «Все», корректировка через модальный `AdjustBalanceDialog` (`clients/balance/adjust`, ответ —
  `ClientDetailResponse`).
- `ClientCardQuickInfo` рендерит плитки шапки как `<dl>` из некликабельных `Tile`; баланс
  показывается всем, право `CAN_VIEW_CLIENT_BALANCE` проверяется только в `FeedBlock` при
  рендере блока `payments`.
- Образец панели баланса уже есть: `OrgBalanceSheet` — `EditSheet size="lg"`, сводка с суммой
  и кнопкой, журнал, вложенная `EditSheet` для пополнения.

Сервер и контракты остаются без изменений: оба эндпоинта уже есть.

## Goals / Non-Goals

**Goals:**
- Один вход в журнал и корректировку баланса — плитка «Баланс»; одна реализация журнала и формы.
- Кликабельность плитки по принятым практикам: семантика кнопки, видимый без наведения признак
  перехода, кольцо фокуса, доступное имя.
- Повторить устройство `OrgBalanceSheet`, чтобы обе панели баланса вели себя одинаково.

**Non-Goals:**
- Серверная проверка `CAN_VIEW_CLIENT_BALANCE` и отдельное право на корректировку.
- Состояние панели в URL и закрытие кнопкой «назад» браузера.
- Пагинация журнала: сервер отдаёт журнал целиком, панель выводит его целиком.
- Общий компонент «журнал баланса» для клиента и организации: типы операций и записи разные,
  объединение — отдельная задача, если понадобится.

## Decisions

### 1. Панель — `ClientBalanceSheet` на `EditSheet`, корректировка — вложенная `EditSheet`

`ClientBalanceSection.tsx` заменяется на `ClientBalanceSheet.tsx`: `EditSheet size="lg"` с
заголовком «Баланс», внутри `EditSheetBody` со сводкой (сумма + «Корректировать») и журналом.
Форма корректировки — `EditSheetForm` во вложенной `EditSheet`, как `ReplenishForm` в
`OrgBalanceSheet`; поля и zod-схема переносятся из `AdjustBalanceDialog` без изменения правил.
Модальный `Dialog` удаляется.

Почему: `EditSheet` уже даёт сдвиг родительской панели при открытой вложенной, защиту
несохранённых изменений и единый футер; модалка поверх правой панели выглядит чужеродно.
Альтернатива — форма прямо в панели над журналом (раскрытие по кнопке): меньше слоёв, но
расходится с образцом `OrgBalanceSheet` и смешивает чтение и ввод в одном скролле.

### 2. Сумма в панели берётся из `ClientDetailResponse`, а не из отдельного запроса

Панель получает `client.balance` из данных карточки; после корректировки ответ
`clients/balance/adjust` (это `ClientDetailResponse`) кладётся в кэш детали через
существующий `onDetail` (`queryClient.setQueryData`), а запрос журнала инвалидируется.
Так плитка и панель читают одно значение и обновляются одновременно, без лишнего запроса.

### 3. Состояние открытия — в `ClientDetailPage`

`ClientCardQuickInfo` остаётся презентационным: получает `onBalanceClick?: () => void`.
`undefined` — плитка некликабельна. `ClientDetailPage` передаёт обработчик только при
`canViewBalance` и рендерит `ClientBalanceSheet` с `open`. Проверка права остаётся в одном
месте, где уже есть сессия.

### 4. Кликабельная плитка: кнопка с растянутой зоной клика

`Tile` получает необязательный `onClick`. Если он задан:
- Плитка — `relative`; внутри `<dd>` значение оборачивается в `<button type="button">`
  с `after:absolute after:inset-0` — вся плитка становится зоной клика, а структура
  `<dl>/<dt>/<dd>` и порядок чтения сохраняются. `div` с `onClick` не используется:
  потерялись бы фокус, Enter/пробел и роль.
- Рядом с подписью — `ChevronRight` (`aria-hidden`), приглушённый; при наведении темнеет.
  Постоянный признак нужен, потому что на сенсорных экранах наведения нет.
- `hover:bg-accent`, `hover:border-foreground/20`, `cursor-pointer`, `active:` — лёгкое
  затемнение; кольцо фокуса — на плитке через `has-[:focus-visible]:ring-2` (кольцо на самой
  кнопке было бы размером с текст суммы).
- `aria-label` из словаря: «Баланс: {сумма}. Открыть историю»; `aria-haspopup="dialog"`.
- Возврат фокуса на плитку при закрытии: панель управляется через `open` без `SheetTrigger`;
  Radix возвращает фокус на ранее сфокусированный элемент — проверяется тестом, при
  необходимости явно через `onCloseAutoFocus`.

Альтернатива — отдельная кнопка «История» в плитке: явнее, но плитка тесная (6 колонок на
широком экране), а маленькая цель нажатия хуже на телефоне.

### 5. Удаление блока `payments`

`"payments"` удаляется из `BLOCK_TYPES`; исчерпывающий `switch` в `FeedBlock` покажет место
удаления. Шаблон карточки пока не хранится на сервере (`defaultTemplate`), поэтому миграция
сохранённых раскладок не нужна. Проп `canViewBalance` у `FeedBlock` уходит вместе с блоком.

### 6. Архивный клиент

Кнопка «Корректировать» скрыта при `client.state !== "ACTIVE"` — сервер всё равно ответит
ошибкой (`requireActive()`); журнал доступен.

## Risks / Trade-offs

- [Журнал теряет видимость в ленте — о долгах узнают только по красной сумме] → красная сумма
  в плитке и алерты шапки остаются; при необходимости вернуть превью — отдельное решение.
- [Без серверной проверки права журнал доступен через API любому сотруднику] → не ухудшается
  относительно текущего состояния; фронт сохраняет прежнюю проверку. Серверная проверка —
  отдельный change.
- [Длинный журнал без пагинации] → для текущих объёмов приемлемо; при росте — пагинация
  в проекции `ClientBalanceHistoryView` и подгрузка в панели.
